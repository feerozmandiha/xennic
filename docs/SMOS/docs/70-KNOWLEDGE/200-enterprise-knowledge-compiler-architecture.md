## 1. Purpose

KNW-201 نخستین سند خانواده Engineering Knowledge (KNW-ENG) و SSOT (تک منبع حقیقت) برای معماری کامپایلر دانش سازمانی SMOS است. این سند تعریف می‌کند که چگونه ورودی‌های خام دانش (از انسان، Agent، سیستم یا منابع خارجی) به دارایی‌های دانش ساختاریافته، معتبر، نرمال‌شده، ثبت‌شده و نمایه‌شده تبدیل می‌شوند — بدون ورود به پیاده‌سازی، فناوری یا کد.

### Why KNW-201 Exists

بدون یک معماری کامپایلر دانش سازمانی:

- فرآیند تبدیل دانش خام به دانش ساختاریافته بدون استاندارد انجام می‌شود
- کیفیت و اعتبار دانش ورودی تضمین نمی‌شود
- نرمال‌سازی دانش به صورت یکسان در همه منابع انجام نمی‌شود
- ردیابی منشأ دانش در فرآیند تبدیل از دست می‌رود
- ثبت و نمایه‌سازی دانش بدون فرآیند مشخص انجام می‌شود
- تکرارپذیری فرآیند کامپایل برای دانش‌های مشابه تضمین نمی‌شود
- خطاهای کامپایل (compile errors) قابل شناسایی و رفع نیستند

KNW-201 این مشکلات را با تعریف **چارچوب معماری کامپایلر دانش سازمانی** حل می‌کند.

| ID      | اصل                               | توضیح                                                                            |
| ------- | --------------------------------- | -------------------------------------------------------------------------------- |
| KCPR-01 | **جداسازی کامپایل از اجرا**       | خط لوله کامپایل (compile-time) از مصرف دانش (runtime) جدا تعریف می‌شود           |

| KCPR-07 | **خطای شفاف**                     | خطاهای کامپایل باید قابل شناسایی، دسته‌بندی و رفع باشند                          |
| KCPR-08 | **خنثی بودن فناوری**              | معماری کامپایلر مستقل از LLM، دیتابیس و فروشنده تعریف می‌شود                     |

## 4. Compiler Philosophy

### فلسفه کامپایل دانش سازمانی

SMOS کامپایل دانش را به عنوان **فرآیند تبدیل سیستماتیک دانش خام به دارایی دانش سازمانی** می‌بیند که:

1. **خطی است** — هر مرحله به مرحله بعد وابسته است و ترتیب ثابتی دارد
2. **اکید است** — خروجی هر مرحله شرط ورود به مرحله بعد است
3. **شفاف است** — تمام تبدیل‌ها قابل ردیابی و حسابرسی هستند
4. **تکرارپذیر است** — برای ورودی یکسان، خروجی یکسان تولید می‌کند
5. **کیفیت‌محور است** — هر مرحله گیت‌های کیفیت مخصوص خود را دارد

### استعاره کامپایلر نرم‌افزار

```markdown
کامپایلر نرم‌افزار: سورس کد → Lexer → Parser → Semantic Analyzer → Optimizer → Code Generator → باینری
کامپایلر دانش SMOS: دانش خام → استخراج → اعتبارسنجی → نرمال‌سازی → تبدیل → ثبت → دارایی دانش
```

### لایه‌های کامپایل

کامپایلر دانش SMOS در سه سطح معنایی عمل می‌کند:

| لایه                  | توضیح                                   | مثال                               |
| --------------------- | --------------------------------------- | ---------------------------------- |
| نحوی (Syntactic)      | اعتبارسنجی ساختار و قالب ورودی          | بررسی JSON Schema، ساختار Markdown |
| معنایی (Semantic)     | اعتبارسنجی معنا و سازگاری با هستی‌شناسی | تطابق با ARCH-003, KNW-000         |
| عملیاتی (Operational) | اعتبارسنجی کاربردپذیری در عملیات        | بررسی قواعد KNW-102, KNW-304       |

```markdown
┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐

▼ ▼ ▼ ▼ ▼ ▼
┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
│Source │ │Structured│ │Validation│ │Normalized│ │Knowledge │ │Registered│
│ Raw Input│ │ Content │ │ Result │ │ Content │ │ Asset │ │Knowledge │
└──────────┘ └──────────┘ └──────────┘ └──────────┘ └──────────┘ └──────────┘

                                                                              ▼
```

## 22. Compiler Governance Model

### مدل حکمرانی کامپایلر

حکمرانی کامپایلر دانش SMOS بر اساس سطوح اختیار (A-0 تا A-4) تعریف می‌شود:

| سطح | عنوان            | اختیارات                                   | مثال                   |
| --- | ---------------- | ------------------------------------------ | ---------------------- |
| A-0 | بدون دسترسی      | فقط مشاهده خروجی‌های ثبت‌شده               | مصرف‌کننده نهایی       |
| A-1 | مصرف‌کننده داخلی | استفاده از خروجی کامپایلر در عملیات        | AI-003, AI-004         |
| A-2 | متقاضی کامپایل   | ارسال ورودی به کامپایلر                    | AI-001, AI-005, AI-013 |
| A-3 | مدیر کامپایلر    | اجرای نشست کامپایل، مدیریت خطاها           | AI-011, معمار دانش     |
| A-4 | مالک کامپایلر    | تعریف قواعد تبدیل، نرمال‌سازی و اعتبارسنجی | معمار دانش             |

### انواع تصمیمات حکمرانی کامپایلر

| نوع         | توضیح                                          | سطح اختیار |
| ----------- | ---------------------------------------------- | ---------- |
| تعریف قاعده | ایجاد قاعده تبدیل یا نرمال‌سازی جدید           | A-4        |
| اجرا        | اجرای یک نشست کامپایل                          | A-3        |
| خطا         | تصمیم‌گیری درباره خطا (re-run, skip, escalate) | A-3        |
| تأیید       | تأیید خروجی کامپایلر برای ثبت                  | A-3        |
| بازبینی     | بازبینی و اصلاح قواعد موجود                    | A-4        |

## 23. Compiler Consistency Model

### مدل سازگاری کامپایلر

سازگاری در کامپایلر دانش SMOS در چهار بعد تعریف می‌شود:

| بعد                       | توضیح                                                          | معیار                                 |
| ------------------------- | -------------------------------------------------------------- | ------------------------------------- |
| Input-Output Consistency  | سازگاری ورودی-خروجی — خروجی با ورودی مبدأ مطابقت دارد          | محتوای خروجی با ورودی سازگار است      |
| Cross-Session Consistency | سازگاری بین نشست‌ها — خروجی‌های مشابه یکسان هستند              | ورودی‌های یکسان → خروجی‌های یکسان     |
| Ontology Consistency      | سازگاری هستی‌شناختی — مفاهیم با ARCH-003 مطابقت دارند          | همه مفاهیم با واژه‌نامه رسمی سازگارند |
| Registry Consistency      | سازگار با نمایه — خروجی با دانش‌های ثبت‌شده قبلی ناسازگار نیست | عدم تضاد با KNW-001                   |

### قواعد سازگاری

| ID     | قاعده                                                         |
| ------ | ------------------------------------------------------------- |
| CCR-01 | خروجی کامپایلر نباید با ورودی مبدأ تضاد داشته باشد            |
| CCR-02 | خروجی کامپایلر نباید با دانش ثبت‌شده قبلی تضاد داشته باشد     |
| CCR-03 | کامپایلر باید برای ورودی‌های یکسان، خروجی‌های یکسان تولید کند |
| CCR-04 | همه مفاهیم در خروجی باید با ARCH-003 مطابقت داشته باشند       |
