## ۱. Purpose

KNW-402 معماری حکمرانی عملیات سازمانی SMOS است. این سند SSOT (تک منبع حقیقت) برای **تعریف اصول، اختیارات، مالکیت، انطباق، اعتبارسنجی، سلسله‌مراتب تأیید و مسئولیت‌پذیری عملیات** برای همه موجودیت‌های عملیاتی تعریف‌شده در KNW-401 است.

### چرا KNW-402 وجود دارد

بدون یک معماری حکمرانی عملیاتی:

- تصمیم‌گیری درباره موجودیت‌های عملیاتی بدون چارچوب و پراکنده انجام می‌شود
- مالکیت و مسئولیت موجودیت‌های عملیاتی مبهم باقی می‌ماند
- انطباق با قواعد کسب‌وکار (KNW-102) در سطح عملیات قابل تضمین نیست
- اعتبارسنجی تغییرات در موجودیت‌های عملیاتی بدون معیار مشخص انجام می‌شود
- استثناها و انحرافات از معماری عملیات بدون فرآیند رسمی مدیریت می‌شوند
- حساب‌پذیری عملیات در سطح سازمانی قابل ردیابی نیست

KNW-402 این مشکلات را با تعریف **چارچوب رسمی حکمرانی عملیات** حل می‌کند.

## ۴. Governance Philosophy

### فلسفه حکمرانی عملیاتی

SMOS حکمرانی عملیاتی را به عنوان **چارچوب تصمیم‌گیری مسئولانه** در معماری عملیات می‌بیند که:

1. **توانمندساز است** — نه محدودکننده. حکمرانی مسیر عملیات را مشخص می‌کند نه مانع را
2. **مبتنی بر ریسک است** — سطح حکمرانی با سطح ریسک عملیات متناسب است
3. **شفاف است** — همه قواعد، اختیارات و مسئولیت‌های عملیاتی مستند و قابل دسترس هستند
4. **قابل اندازه‌گیری است** — اثربخشی حکمرانی عملیات با شاخص‌های مشخص ارزیابی می‌شود
5. **تکامل‌پذیر است** — چارچوب حکمرانی عملیات در طول زمان بر اساس یادگیری سازمانی بهبود می‌یابد

### اصول هستی‌شناسی حکمرانی عملیات

| اصل                                        | توضیح                                                 |
| ------------------------------------------ | ----------------------------------------------------- |
| **هر تصمیم عملیاتی یک سطح اختیار دارد**    | تصمیمات در سطوح A-0 تا A-4 طبقه‌بندی می‌شوند          |
| **هر موجودیت عملیاتی یک مالک دارد**        | هر موجودیت عملیاتی یک مالک مشخص دارد                  |
| **هر قاعده عملیاتی یک منبع دارد**          | قواعد حکمرانی از KNW-102 یا KNW-402 مشتق می‌شوند      |
| **هر استثنای عملیاتی یک انقضا دارد**       | استثناها موقت هستند و پس از انقضا نیاز به تمدید دارند |
| **حکمرانی عملیات مستقل از پیاده‌سازی است** | چارچوب حکمرانی برای همه عملیات‌ها یکسان است           |

## ۹. Ownership Model

### مدل مالکیت عملیاتی

هر موجودیت عملیاتی دارای یک **مالک (Owner)** و یک **متولی (Steward)** است.

| نقش                   | مسئولیت                                          | سطح اختیار |
| --------------------- | ------------------------------------------------ | ---------- |
| مالک (Owner)          | تصمیم‌گیری نهایی درباره موجودیت عملیاتی          | A-3 یا A-4 |
| متولی (Steward)       | نگهداری و به‌روزرسانی روزانه موجودیت عملیاتی     | A-2        |
| تولیدکننده (Producer) | ایجاد و مستندسازی موجودیت عملیاتی                | A-1 یا A-2 |
| مصرف‌کننده (Consumer) | استفاده از موجودیت عملیاتی در تصمیمات و فرآیندها | A-0        |

### مالکیت موجودیت‌های عملیاتی

| موجودیت                       | مالک پیش‌فرض | متولی پیش‌فرض |
| ----------------------------- | ------------ | ------------- |

| OPCAP-\* (قابلیت‌های عملیاتی) | مدیر عملیات  | مهندس عملیات  |
| OPF-\* (کارکردهای عملیاتی)    | مدیر عملیات  | مهندس عملیات  |
| OPE-\* (موجودیت‌های عملیاتی)  | معمار عملیات | متولی دانش    |

| OP-REG-\* (عملیات ثبت‌شده)    | مدیر عملیات  | اپراتور       |

## ۱۰. Accountability Model

### مدل حساب‌پذیری

| اصل                    | توضیح                                               |
| ---------------------- | --------------------------------------------------- |
| **تک مسئول**           | هر تصمیم و تغییر عملیاتی یک مسئول نهایی دارد        |
| **عدم اشتراک مسئولیت** | مسئولیت دو نفر برای یک موجودیت عملیاتی مجاز نیست    |
| **قابل ردیابی**        | همه تصمیمات عملیاتی به یک شخص/نقش قابل انتساب هستند |
| **زمان‌دار**           | مسئولیت تا زمان انتقال رسمی پابرجاست                |
| **مستند**              | همه تصمیمات عملیاتی در رجیستری حکمرانی ثبت می‌شوند  |

| A-3 | مدیر عملیات  | جهت‌گیری و تکامل دامنه‌های عملیاتی           |
