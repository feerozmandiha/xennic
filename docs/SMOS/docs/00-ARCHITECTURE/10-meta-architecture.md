## ۱. معرفی

این سند **معماری متا** یا **الگوی مفهومی عملیاتی** SMOS را تعریف می‌کند.
این یک سند معماری است — نه مستندات عملیاتی.
تمام اجزای SMOS (انسان، Agent، گردش کار، دانش) از این معماری مشتق می‌شوند.

## ۲. اصول معماری متا

| اصل                 | توضیح                                                        |
| ------------------- | ------------------------------------------------------------ |
| **مقیاس سازمانی**   | طراحی برای سازمان، نه یک تیم                                 |
| **AI First**        | Agentها شهروند درجه یک سیستم هستند                           |
| **Human First**     | انسان در حلقه تصمیم‌گیری باقی می‌ماند                        |
| **دانش‌محور**       | هر عملیات دانش تولید می‌کند، هر دانش عملیات را بهبود می‌بخشد |
| **خودکارسازی‌پذیر** | هر فرایند قابل خودکارسازی است مگر صریحاً استثنا شده باشد     |
| **مستقل از پلتفرم** | پلتفرم‌ها قابل تعویض هستند                                   |
| **آینده‌نگر**       | RAG، MCP، Multi-Agent از روز اول در نظر گرفته شده‌اند        |

## ۴. سلسله‌مراتب اهداف (Goal Hierarchy)

```
چشم‌انداز کسب‌وکار (Business Vision)
  │
  ├── اهداف کسب‌وکار (Business Objectives)
  │    └── اهداف بازاریابی (Marketing Objectives)
  │         └── اهداف رسانه (Media Objectives)
  │              └── اهداف کمپین (Campaign Objectives)
  │                   └── اهداف پلتفرم (Platform Objectives)
  │                        └── اهداف محتوا (Content Objectives)
  │                             └── اهداف عملکرد (Performance Objectives)
  │
  └── شاخص‌های کلیدی عملکرد (KPIها)
       └── هر سطح KPIهای خاص خود را دارد
```

### تعریف هر سطح

| سطح                 | مثال                                  | بازه زمانی | اندازه‌گیری   |
| ------------------- | ------------------------------------- | ---------- | ------------- |
| **چشم‌انداز**       | رهبر بازار رسانه‌های اجتماعی در ایران | ۵-۱۰ سال   | سهم بازار     |
| **اهداف کسب‌وکار**  | افزایش درآمد ۳۰٪                      | سالانه     | درآمد         |
| **اهداف بازاریابی** | افزایش آگاهی از برند ۵۰٪              | فصلی       | آگاهی از برند |
| **اهداف رسانه**     | افزایش تعامل ۴۰٪                      | ماهانه     | نرخ تعامل     |
| **اهداف کمپین**     | راه‌اندازی کمپین محصول جدید           | ۱-۳ ماه    | ROI کمپین     |
| **اهداف پلتفرم**    | رشد ۲۰٪ فالوور اینستاگرام             | ماهانه     | رشد مخاطب     |
| **اهداف محتوا**     | تولید ۳۰ قطعه محتوا در هفته           | هفتگی      | حجم تولید     |
| **اهداف عملکرد**    | نرخ تعامل > ۵٪                        | لحظه‌ای    | نرخ تعامل     |

## ۵. سلسله‌مراتب محتوا (Content Hierarchy)

```
ماموریت (Mission)
  │
  └── کمپین (Campaign) — مجموعه‌ای از فعالیت‌ها با هدف مشخص
       │
       └── ستون محتوا (Content Pillar) — حوزه‌های همیشگی محتوا
            │
            └── سری محتوا (Content Series) — دنباله‌ای از محتوای مرتبط
                 │
                 └── قطعه محتوا (Content Piece) — واحد پایه محتوا
                      │
                      ├── نسخه پلتفرم (Platform Version) — بومی‌سازی برای پلتفرم
                      │    └── واریانت محتوا (Content Variant) — تغییرات A/B
                      │         └── انتشار (Publication) — یک بار انتشار
                      │
                      └── دارایی (Asset) — فایل‌های ضمیمه
                           └── نسخه دارایی (Asset Version) — تغییرات فایل
```

### کاردینالیتی

| رابطه                      | نوع | توضیح                                  |
| -------------------------- | --- | -------------------------------------- |
| Mission → Campaign         | 1:N | یک مأموریت می‌تواند N کمپین داشته باشد |
| Campaign → Pillar          | 1:N | یک کمپین شامل N ستون محتواست           |
| Pillar → Series            | 1:N | یک ستون شامل N سری است                 |
| Series → Piece             | 1:N | یک سری شامل N قطعه است                 |
| Piece → Platform Version   | 1:N | یک قطعه برای N پلتفرم بومی‌سازی می‌شود |
| Platform Version → Variant | 1:N | هر نسخه N واریانت A/B دارد             |
| Variant → Publication      | 1:1 | هر واریانت یک‌بار منتشر می‌شود         |
| Piece → Asset              | 1:N | هر قطعه N دارایی دارد                  |

## ۶. سلسله‌مراتب موجودیت‌ها (Entity Stack)

```
Enterprise (سازمان)
  └── Brand (برند)
       └── Product/Service (محصول/خدمت)

```

## ۷. قواعد معماری متا

### ۷.۱ قاعده سطوح

1. هر سطح از Goal Hierarchy به سطح بالاتر پاسخ می‌دهد
2. هر سطح KPIهای مخصوص خود را دارد
3. اهداف از بالا به پایین جاری می‌شوند
4. گزارش‌ها از پایین به بالا جمع می‌شوند

### ۷.۲ قاعده اشیا

1. هر شیء یک ID یکتا دارد
2. هر شیء یک والد دارد (جز لایه Vision)
3. هر شیء یک چرخه حیات دارد
4. هر شیء یک مالک دارد
5. هر شیء یک منبع حقیقت واحد دارد

### ۷.۳ قاعده جریان

1. اطلاعات از Vision به سمت Archive جریان دارد
2. بازخورد از Analytics به سمت Learning برمی‌گردد
3. هیچ گره‌ای بدون ورودی و خروجی نیست
4. همه چیز قابل ردیابی است (Audit Trail)
