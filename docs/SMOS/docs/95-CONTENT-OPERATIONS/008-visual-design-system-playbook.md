## ۱. Purpose — هدف

این سند راهنمای عملیات روزانه تیم طراحی بصری Xennic است. هر آنچه یک طراح برای دریافت درخواست, تولید دارایی بصری, بازبینی, تأیید و تحویل نیاز دارد در این سند تعریف شده است.

این سند معماری نیست — دستورالعمل اجرای روزانه طراحی است.

## ۳. Design Request Intake — فرآیند دریافت درخواست طراحی

### مراحل دریافت درخواست

```
درخواست → ثبت در ابزار → ارزیابی → اولویت‌بندی → تخصیص → اجرا → بازبینی → تحویل
```

### اطلاعات الزامی درخواست

| فیلد               | توضیح                                      | اجباری |
| ------------------ | ------------------------------------------ | ------ |
| عنوان درخواست      | شرح کوتاه طرح مورد نیاز                    | بله    |
| نوع دارایی         | پست, استوری, اینفوگرافیک, ویدئو, بنر       | بله    |
| پلتفرم هدف         | اینستاگرام, لینکدین, وبسایت و...           | بله    |
| ابعاد و مشخصات فنی | اندازه, فرمت, وضوح                         | بله    |
| مهلت تحویل         | تاریخ و ساعت دقیق                          | بله    |
| brief خلاقیت       | پیام اصلی, مخاطب, لحن مورد نظر             | بله    |
| محتوای متنی        | متن نهایی‌شده برای قرارگیری در طرح         | بله    |
| مرجع بصری          | نمونه, رنگ‌ها, لوگو, فونت                  | خیر    |
| اولویت             | P1 (فوری), P2 (عادی), P3 (برنامه‌ریزی‌شده) | بله    |

### چک‌لیست دریافت درخواست

- [ ] درخواست در ابزار مدیریت تسک ثبت شده
- [ ] همه فیلدهای اجباری تکمیل شده
- [ ] brief خلاقیت واضح و کامل است
- [ ] محتوای متنی نهایی‌شده موجود است (متن ناقص = تأخیر)
- [ ] مهلت تحویل واقع‌بینانه است
- [ ] منابع مورد نیاز (عکس, آیکون, فونت) مشخص شده

## ۴. Project Brief Requirements — الزامات brief پروژه

### ساختار استاندارد brief

| بخش              | محتوا                  | مثال                              |
| ---------------- | ---------------------- | --------------------------------- |
| **عنوان**        | نام کوتاه و گویا       | پست معرفی محصول جدید              |
| **هدف**          | هدف اصلی طراحی         | افزایش آگاهی از برند              |
| **مخاطب**        | چه کسی می‌بیند         | مدیران فناوری ۳۰-۴۵ سال           |
| **پیام کلیدی**   | یک جمله اصلی           | Xennic راه‌حل مدیریت محتوا        |
| **لحن بصری**     | حس کلی طرح             | حرفه‌ای, مدرن, قابل اعتماد        |
| **ابعاد**        | اندازه خروجی           | 1080×1080px (اینستاگرام)          |
| **رنگ‌های اصلی** | رنگ‌های برند           | Xennic Blue: #1A3A5C              |
| **فونت**         | فونت متن و عنوان       | IRANSans (متن), Vazirmatn (عنوان) |
| **مدیا**         | تصویر/ویدئوی مورد نیاز | عکس محصول از پوشه Brand Assets    |
| **CTA**          | دعوت به اقدام          | همین الان دمو را ببینید           |
| **خط‌قرمز**      | چه چیزی ممنوع است      | بدون تصویر انسان, بدون رنگ قرمز   |

### قاعده طلایی brief

> **متن ناقص = طراحی ناقص.** طراح هرگز شروع به طراحی نمی‌کند مگر اینکه متن نهایی موجود باشد.

## ۶. Asset Version Management — مدیریت نسخه دارایی‌ها

### قواعد نسخه‌بندی

| وضعیت               | پسوند      | توضیح                  |
| ------------------- | ---------- | ---------------------- |
| پیش‌نویس اولیه      | \_v1       | اولین نسخه             |
| اصلاح پس از بازبینی | \_v2       | اعمال نظرات بازبینی    |
| اصلاح نهایی         | \_vFinal   | نسخه تأیید شده نهایی   |
| آرشیو شده           | \_archived | نسخه‌های قدیمی غیرفعال |

### چک‌لیست مدیریت نسخه

- [ ] هر نسخه جدید با پسوند عددی ذخیره شده
- [ ] نسخه‌های قدیمی حذف نشده‌اند (فلاک نشده‌اند)
- [ ] نسخه نهایی با \_vFinal مشخص شده
- [ ] فایل‌های منبع (PSD, AI) در پوشه مخصوص نگهداری می‌شوند
- [ ] فایل‌های خروجی (PNG, JPG, MP4) در پوشه خروجی ذخیره می‌شوند

### ساختار پوشه‌ها

```
Design Assets/
├── 01-Projects/           ← پروژه‌های فعال
│   ├── 2026-07/
│   │   ├── IG-product-launch/
│   │   │   ├── Source/    ← فایل‌های منبع (PSD, AI)
│   │   │   ├── Export/    ← فایل‌های خروجی (PNG, JPG)
│   │   │   └── Reference/ ← منابع مرجع
│   │   └── LI-q2-report/
│   └── ...
├── 02-Brand Assets/       ← دارایی‌های ثابت برند
│   ├── Logo/
│   ├── Colors/
│   ├── Fonts/
│   └── Templates/
├── 03-Reference/          ← تصاویر مرجع و الهام
└── 04-Archived/           ← پروژه‌های بایگانی‌شده
```

## ۹. Image and Icon Sourcing — تهیه تصویر و آیکون

| نوع         | منبع                        | شرایط                               |
| ----------- | --------------------------- | ----------------------------------- |
| تصویر استوک | پلتفرم‌های مجاز استوک       | بررسی لایسنس قبل از استفاده         |

- [ ] کیفیت تصویر ≥۱۰۸۰px برای دیجیتال

- [ ] تصویر حاوی محتوای ممنوعه نیست
- [ ] فرمت فایل مناسب است (PNG برای شفافیت, JPG برای عکس)

## ۱۱. Design Review Workflow — جریان بازبینی طراحی

### مراحل بازبینی

```
طراحی اولیه → بازبینی درون‌تیمی → اعمال اصلاحات → بازبینی مدیر تولید → اصلاحات نهایی → تأیید نهایی
```

### چک‌لیست بازبینی طراحی

| معیار          | بررسی                     | حداقل استاندارد |
| -------------- | ------------------------- | --------------- |
| اندازه و ابعاد | مطابق مشخصات فنی باشد     | ۱۰۰٪            |
| رنگ‌های برند   | مطابق پالت رسمی           | ۱۰۰٪            |
| فونت           | فونت‌های مجاز استفاده شده | ۱۰۰٪            |
| لوگو           | اندازه و موقعیت صحیح      | ۱۰۰٪            |
| وضوح تصویر     | حداقل ۷۲dpi برای دیجیتال  | ≥۷۲dpi          |
| کنتراست        | خوانایی متن تضمین شده     | ≥۴.۵:۱          |
| فضای خالی      | حاشیه کافی در اطراف محتوا | ≥۱۰٪            |
| تعادل بصری     | توزیع مناسب عناصر         | بله             |
| پیام‌رسانی     | پیام اصلی واضح است        | بله             |

### نقش‌ها در بازبینی

| مرحله              | بازبین      | خروجی           |
| ------------------ | ----------- | --------------- |
| بازبینی درون‌تیمی  | طراح همکار  | بازخورد اصلاحی  |
| بازبینی مدیر تولید | مدیر تولید  | تأیید/عدم تأیید |
| بازبینی نهایی      | مدیر عملیات | تأیید نهایی     |

## ۱۹. Weekly Design Review — بازبینی هفتگی طراحی

### جلسه بازبینی هفتگی (سه‌شنبه — ۳۰ دقیقه)

**شرکت‌کنندگان:** طراح ارشد, مدیر تولید, مدیر عملیات

| بخش                  | مدت      | محتوا                              |
| -------------------- | -------- | ---------------------------------- |
| مرور دستاوردها       | ۵ دقیقه  | بررسی طراحی‌های تکمیل‌شده هفته قبل |
| بررسی تسک‌های جاری   | ۱۰ دقیقه | وضعیت طراحی‌های در حال انجام       |
| بازبینی کیفیت        | ۵ دقیقه  | بررسی نمونه‌های برجسته و مشکلات    |
| برنامه‌ریزی هفته بعد | ۵ دقیقه  | اولویت‌بندی درخواست‌های جدید       |
| موانع و مشکلات       | ۵ دقیقه  | شناسایی و حل موانع                 |

### گزارش هفتگی طراحی

| بخش                          | محتوا        |
| ---------------------------- | ------------ |
| تعداد طراحی‌های تکمیل‌شده    | شمارش دقیق   |
| تعداد طراحی‌های در حال انجام | با وضعیت     |
| میانگین زمان تولید           | ساعت/طراحی   |
| تعداد درخواست‌های جدید       | ورودی هفته   |
| مشکلات و موانع               | لیست و وضعیت |

## ۲۱. Inputs — ورودی‌ها

- درخواست‌های طراحی از مدیر تولید
- brief خلاقیت از نویسندگان و استراتژیست
- محتوای متنی نهایی‌شده
- تقویم تحریریه (OPS-004)
- دارایی‌های برند (لوگو, رنگ, فونت)
- بازخورد بازبینی‌ها

---

## ۲۲. Outputs — خروجی‌ها

- دارایی‌های بصری نهایی (تصویر, ویدئو, اینفوگرافیک)
- فایل‌های خروجی با فرمت استاندارد
- فایل‌های منبع آرشیو شده
- گزارش هفتگی طراحی
- درخواست‌های به‌روزرسانی سیستم طراحی
