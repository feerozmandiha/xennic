> **شناسه:** GOV-002
> **وضعیت:** پیش‌نویس

> **به‌روزرسانی:** 2026-06-27
> **مسئول:** مهندس حکمرانی سازمانی
> **وابستگی:** [CON-000](../05-CONSTITUTION/00-constitution.md), [ARCH-031](./../00-ARCHITECTURE/31-change-management.md), [GOV-001](./01-documentation-standards.md)
> **مخاطب:** human, agent, n8n, mcp

## ۱. معرفی

این سند **نظام نسخه‌بندی همه اسناد SMOS** را تعریف می‌کند.
نسخه‌بندی ابزاری است برای ردیابی تغییرات، اطمینان از یکپارچگی و تسهیل ممیزی.

### دامنه

- همه اسناد در همه ماژول‌ها (ARCH-_, GOV-_, CON-_, PLAT-_, ...)
- همه فایل‌های کانفیگ و داده (در آینده)
- همه ADRها (ARCH-034)

---

## ۲. طرح نسخه‌بندی (Versioning Scheme)

### ۲.۱ قالب اصلی

```
X.Y.Z[-pre-release]
```

| بخش             | معنی                               | مثال          | محدوده |
| --------------- | ---------------------------------- | ------------- | ------ |
| **X (MAJOR)**   | تغییر اساسی — بازنویسی کامل        | ۱.۰.۰ → ۲.۰.۰ | ۰–∞    |
| **Y (MINOR)**   | افزودن بخش جدید بدون شکست backward | ۱.۰.۰ → ۱.۱.۰ | ۰–∞    |
| **Z (PATCH)**   | اصلاح جزئی — تایپو، قالب‌بندی      | ۱.۰.۰ → ۱.۰.۱ | ۰–∞    |
| **pre-release** | وضعیت موقت پیش از انتشار           | -draft, -rc.1 | متن    |

### ۲.۲ شناسه‌های پیش‌انتشار (Pre-release)

| شناسه       | معنی                              | مجاز برای  |
| ----------- | --------------------------------- | ---------- |
| `-draft`    | پیش‌نویس در حال نگارش             | Maintainer |
| `-rc.N`     | انتشار کاندید (Release Candidate) | Reviewer   |
| بدون suffix | انتشار نهایی (Published)          | Approver   |

**ترتیب اولویت:** `-draft` < `-rc.1` < `-rc.2` < ... < (بدون suffix)

---

## ۳. قواعد افزایش نسخه

### ۳.۱ MAJOR (X)

افزایش می‌یابد وقتی:

- بازنویسی کامل محتوای سند
- تغییر در مبانی نظری یا معماری سند
- تغییر در قواعد الزام‌آور سند که با نسخه قبلی ناسازگار است
- سند جایگزین سند دیگری می‌شود (SUPERSEDE)

### ۳.۲ MINOR (Y)

افزایش می‌یابد وقتی:

- اضافه شدن بخش جدید
- اضافه شدن جدول یا داده جدید
- تغییر در ساختار بخش‌ها (بدون تغییر محتوای اصلی)
- به‌روزرسانی ارجاعات

### ۳.۳ PATCH (Z)

افزایش می‌یابد وقتی:

- اصلاح تایپوگرافی
- اصلاح قالب‌بندی
- اصلاح لینک‌های شکسته
- اصلاح خطاهای نگارشی

### ۳.۴ قواعد ترکیبی

- در هر انتشار فقط یک بخش افزایش می‌یابد
- با افزایش MAJOR، MINOR و PATCH به صفر بازمی‌گردند
- با افزایش MINOR، PATCH به صفر بازمی‌گردد
- تغییرات PATCH مستقل از MINOR و MAJOR هستند

## ۴. نسخه صفر (0.x.x)

| نسخه      | معنی                     |
| --------- | ------------------------ |
| **۰.۱.۰** | نسخه اولیه پیش‌نویس      |
| **۰.۲.۰** | پیش‌نویس با بخش‌های جدید |
| **۰.۹.۰** | پیش‌نویس نزدیک به انتشار |
| **۱.۰.۰** | اولین انتشار رسمی        |

- نسخه ۰.x.x نشانه سند ناپایدار است
- سند در ۰.x.x فقط برای انسان و Agent (با احتیاط) قابل استفاده است
- n8n و MCP نباید به اسناد ۰.x.x وابسته شوند

## ۵. نسخه‌بندی بر اساس وضعیت سند

| وضعیت سند  | فرمت نسخه                 | مجاز برای n8n/MCP       |
| ---------- | ------------------------- | ----------------------- |
| Proposal   | ۰.۱.۰-draft               | خیر                     |
| Draft      | ۰.x.x-draft               | خیر                     |
| Review     | ۰.x.x-rc.N                | فقط با تگ `REVIEW`      |
| Approved   | ۰.x.x-rc.N                | فقط با تأیید صریح       |
| Published  | X.Y.Z                     | بله                     |
| Deprecated | X.Y.Z (بدون تغییر)        | خیر — فقط اطلاع‌رسانی   |
| Superseded | X.Y.Z (بدون تغییر)        | خیر — هدایت به سند جدید |
| Archived   | آخرین نسخه پیش از بایگانی | خیر                     |

## ۶. تغییرات و ثبت (Change Log)

هر سند باید Change Log داشته باشد — طبق [GOV-001](./01-documentation-standards.md) §۳.۳:

```markdown
## تغییرات

| نسخه  | تاریخ      | تغییر            | توسط    |
| ----- | ---------- | ---------------- | ------- |
| ۱.۰.۱ | 2026-07-01 | اصلاح تایپوگرافی | مهندس A |
| ۱.۰.۰ | 2026-06-26 | انتشار اولیه     | مهندس A |
```

**قواعد:**

- جدیدترین نسخه در بالای جدول
- تاریخ به فرمت YYYY-MM-DD
- «توسط»: نقش یا نام و نقش — ترجیحاً شناسه نقش از RACI (ARCH-030)
- شرح تغییر: مختصر، دقیق و قابل فهم

## ۷. قواعد عمومی

| قاعده      | توضیح                                                          |
| ---------- | -------------------------------------------------------------- |
| GOV-002-01 | هیچ سندی بدون نسخه معتبر نیست                                  |
| GOV-002-02 | افزایش نسخه توسط Maintainer انجام می‌شود                       |
| GOV-002-03 | نسخه در هدر سند و در Change Log ثبت می‌شود                     |
| GOV-002-04 | اسناد Published هرگز از نظر MAJOR/MINOR کاهش نمی‌یابند         |
| GOV-002-05 | اسناد Archived هرگز ویرایش یا تغییر نسخه نمی‌دهند              |
| GOV-002-06 | هر تغییر در سند = افزایش حداقل PATCH                           |
| GOV-002-07 | تغییرات Cosmetic (تایپو، فاصله) می‌توانند PATCH را افزایش دهند |

## ۸. تطابق

- نگهبان (Custodian) هر ماژول مسئول تطابق نسخه‌بندی اسناد ماژول خود است
- نقض قواعد نسخه‌بندی یک تخلف حکمرانی محسوب می‌شود
- موارد استثنا با ADR غیرقابل حذف هستند
