- تسهیل پردازش خودکار فراداده و ارجاعات

## ۳. ساختار پایه سند (Document Template)

### ۳.۱ هدر (Header)

هر سند SMOS باید با بلوک فراداده زیر آغاز شود:

```markdown
# عنوان سند — عنوان انگلیسی

> **شناسه:** MODULE-NNN
> **وضعیت:** [پیش‌نویس / منتشرشده / منسوخ / جایگزین‌شده / بایگانی]
> **نسخه:** X.Y.Z[-suffix]
> **به‌روزرسانی:** YYYY-MM-DD
> **مسئول:** نام نقش (نام شخص اختیاری)
> **وابستگی:** [شناسه](./مسیر), [شناسه](./مسیر)
> **مخاطب:** human, agent, n8n, mcp
```

**قواعد:**

- عنوان فارسی در خط اول، عنوان انگلیسی پس از `—` (خط تیره بلند)
- هدر با `>` در ابتدای هر خط
- فیلدها با ترتیب بالا — بدون جابجایی
- شناسه طبق [GOV-003](./03-naming-conventions.md)
- نسخه طبق [GOV-002](./02-versioning.md)
- مخاطب: حداقل `human` و حداکثر مجموعه `human, agent, n8n, mcp`

### ۳.۲ بدنه اصلی

بدنه سند شامل بخش‌های زیر است (به ترتیب):

| بخش              | اجباری؟ | توضیح                                             |
| ---------------- | ------- | ------------------------------------------------- |
| معرفی (۱. معرفی) | اجباری  | معرفی موضوع، دامنه و هدف سند                      |
| بخش‌های اصلی     | اجباری  | محتوای تخصصی — شماره‌گذاری ۲. ۳. ۴. ...           |
| تغییرات          | اجباری  | جدول تغییرات — فرمت [GOV-002](./02-versioning.md) |

### ۳.۳ پاورقی / بخش تغییرات (Change Log)

```markdown
## تغییرات

| نسخه  | تاریخ      | تغییر     | توسط       |
| ----- | ---------- | --------- | ---------- |
| X.Y.Z | YYYY-MM-DD | شرح تغییر | نقش یا نام |
```

## ۴. قواعد نگارش (Writing Conventions)

### ۴.۱ زبان

- **زبان اصلی:** فارسی حرفه‌ای (نثر رسمی، روان، بدون حشو)
- **عنوان انگلیسی:** پس از `—` در خط عنوان سند
- **اصطلاحات فنی:** تلفظ فارسی در متن، معادل انگلیسی در پرانتز در اولین استفاده
- **اختصارات:** در اولین استفاده، شکل کامل + مخفف در پرانتز

### ۴.۲ قالب‌بندی

- **سرفصل‌ها:** `##` برای بخش اصلی، `###` برای زیربخش، `####` برای زیرزیربخش
- **تأکید:** `**` برای پررنگ (مفاهیم کلیدی، اصطلاحات)، `*` برای ایتالیک (ارجاعات لاتین)
- **کد:** `` ` `` برای inline (شناسه‌ها، نام فایل‌ها، مقادیر)
- **بلوک کد:** ``` برای نمونه‌ها، قالب‌ها، تنظیمات
- **جداول:** برای داده‌های ساختاریافته — با هدر و ردیف‌های مشخص
- **فاصله:** یک خط خالی بین بخش‌ها، بدون فاصله اضافی

### ۴.۳ نمودارها

نمودارها باید به صورت ASCII Art یا متن‌محور باشند:

```markdown
┌──────────┐
│ Sample │
└──────────┘
```

Modalها، chartها و تصاویر گرافیکی مجاز نیستند — مگر در مستندات بازاریابی / برند.

### ۴.۴ ارجاع به اسناد دیگر

طبق [GOV-004](./04-cross-references.md):

```markdown
[شناسه](./مسیر-نسبی)
[CON-000](../05-CONSTITUTION/00-constitution.md)
```

## ۵. انواع سند و قالب اختصاصی

### ۵.۱ استراتژیک (Strategic)

- **ماژول‌ها:** ۰۰-ARCHITECTURE, ۰۵-CONSTITUTION, ۱۰-GOVERNANCE
- **فرکانس به‌روزرسانی:** فصلی / سالانه
- **ویژگی:** همیشه‌سبز (evergreen)، پایدار، کم‌تغییر

### ۵.۲ پلتفرم (Platform)

- **ماژول‌ها:** ۲۰-PLATFORMS, ۲۲-BRAND, ۲۴-EDITORIAL
- **فرکانس به‌روزرسانی:** ماهانه / فصلی
- **ویژگی:** وابسته به پلتفرم خارجی، نیازمند بازبینی دوره‌ای

### ۵.۳ عملیاتی (Operational)

- **ماژول‌ها:** ۵۰-OPERATIONS, ۵۵-REPORTS, ۶۰-METRICS
- **فرکانس به‌روزرسانی:** هفتگی / روزانه
- **ویژگی:** متغیر، وابسته به زمان، نیازمند به‌روزرسانی مداوم

### ۵.۴ مرجع (Reference)

- **ماژول‌ها:** ۴۵-KNOWLEDGE, ۷۰-REFERENCE, ۸۰-TRAINING
- **فرکانس به‌روزرسانی:** در صورت نیاز
- **ویژگی:** پایدار، قابل جستجو، بدون تاریخ انقضا

### ۵.۵ خودکارسازی (Automation)

- **ماژول‌ها:** ۳۰-AUTOMATION, ۳۵-PROMPTS, ۴۰-AI-AGENTS
- **فرکانس به‌روزرسانی:** هر sprint / در تغییر
- **ویژگی:** قابل اجرا، دقیق، با versioning سخت‌گیرانه
