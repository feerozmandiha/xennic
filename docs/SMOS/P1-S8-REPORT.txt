9. RISKS
--------------------------------------------------------------------------------
Identified risks and mitigations:

  1. Template complexity (MEDIUM)
     → 34 sections may seem overwhelming for authors
     → Mitigation: Reading guide, clear examples in each section,

  2. Rigidity (LOW)
     → Strict 34-section structure may not fit every platform perfectly
     → Mitigation: Empty sections allowed (with "Not applicable" marker)
       but never removed

  3. JSON schema drift (MEDIUM)
     → JSON schemas may fall out of sync with actual PLAT-* content
     → Mitigation: Automated validation before each PLAT-* publication

  4. Quality gate bottlenecks (MEDIUM)
     → 7 sequential gates may slow down publication
     → Mitigation: L1/L2/L3 approval levels, gates can run in parallel
       where dependencies permit

  5. Cross-PLAT duplication (LOW)
     → Similar platforms may have overlapping content
     → Mitigation: VAL-033 (no duplicate strategic content),
       VAL-034 (no cross-platform content)


10. OPEN QUESTIONS
--------------------------------------------------------------------------------
  1. Should the 34-section structure be validated by a CI/CD pipeline?
     Currently validation is manual. A CI/CD validation script would
     enforce VAL-001 through VAL-035 automatically.

  2. Should PLAT-000 include a YAML frontmatter alternative to the
     current Markdown header block? Some agents process YAML more
     efficiently than Markdown blockquotes.

  3. Should there be a condensed "Quick Start" version for human
     authors, separate from the full PLAT-000 specification?

  4. Should PLAT-000 include a pre-filled template file (e.g.,
     `template-plat-nnn.md`) that authors copy as a starting point?

  5. Should the compliance checklist be machine-readable (JSON)
     in addition to the current Markdown checkbox format?
