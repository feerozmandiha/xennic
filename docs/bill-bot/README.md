## ۱. خلاصه مدیریتی

«ربات تحلیل قبض برق» یک ربات گفتگوگر روی دو پیام‌رسان **تلگرام** و **بله** است که در **فاز اول** این چرخه را کامل انجام می‌دهد:

1. **دریافت قبض** — مشترک، قبض برق را به‌صورت **PDF یا تصویر** برای ربات ارسال می‌کند.
2. **استخراج اطلاعات** — محتوای قبض با OCR خوانده شده و تمام فیلدهای آن (شناسه قبض/پرداخت، دوره، کارکرد، شاخص‌ها، ریز مبالغ و…) استخراج و **به‌صورت جدول دقیق** در چت نمایش داده می‌شود.
3. **تحلیل هوشمند** — موتور محاسبه بر اساس **جدیدترین تعرفه‌های توانیر (سال ۱۴۰۵)** قبض را بازآرایی می‌کند: جایگاه مشترک نسبت به **الگوی مصرف**، پله‌های تعرفه، هزینه مازاد، جریمه/پاداش اوج‌بار و توصیه‌های بهینه‌سازی؛ در صورت اتصال، یک لایه LLM نیز روایت تحلیلی فارسی تولید می‌کند.
4. **خروجی‌ها** — دو دکمه پایانی:
   - **«چاپ گزارش PDF»** → گزارش کامل و برند‌شده به‌صورت PDF برای کاربر ارسال می‌شود.
   - **«درخواست مشاوره»** → دو زیرمسیر: **پیام خصوصی (PV)** یا **تماس تلفنی**؛ درخواست به همراه خلاصه پرونده برای تیم مشاوره ارسال و کد پیگیری صادر می‌شود.

معماری چندسکویی است: یک هسته واحد (Core) با دو آداپتور پلتفرم. API پیام‌رسان بله با API ربات تلگرام سازگار است (پایه `tapi.bale.ai`)، بنابراین بیش از ۹۰٪ کد بین دو سکو مشترک است. [1](https://docs.bale.ai/)

## ۳. اصول کلیدی طراحی

- **دقت مقدم بر سرعت:** اگر OCR به فیلدی اطمینان نکرده باشد، آن فیلد «نامشخص» علامت‌گذاری شده و از کاربر تأیید گرفته می‌شود؛ هرگز عدد حدسی به‌عنوان عدد قطعی محاسبه نمی‌شود.
- **قابل تنظیم بودن تعرفه:** تمام جداول تعرفه، هزینه تأمین و ضرایب در یک ماژول داده (`src/tariff/tavanir1405.ts`) متمرکز و از طریق env قابل بازنویسی‌اند؛ با ابلاغ تعرفه سال جدید فقط داده عوض می‌شود، نه کد.
- **هم‌ترازی با Xennic:** ربات از `vision-service` موجود ریپازیتوری (پایپ‌لاین OCR/استخراج قبض با PaddleOCR/Tesseract/LLM-Vision) به‌عنوان مسیر اصلی OCR استفاده می‌کند و در نبود آن، موتور استخراج محلی (regex فارسی) فعال می‌شود. خروجی با اسکیمای `BillData` سرویس بینایی هم‌شکل است.
- **بدون وابستگی اجباری سنگین:** هسته ربات با Node.js ≥ 22 و بدون هیچ وابستگی npm اجرا و تست می‌شود؛ کتابخانه‌های PDF/LLM اختیاری و با بارگذاری پویا اضافه می‌شوند.
- **فارسی‌اول:** همه پیام‌ها، جدول‌ها و گزارش‌ها RTL و با اعداد فارسی هستند.

## ۴. خلاصه فنی (فاز اول)

| بخش         | انتخاب                                                                                     |
| ----------- | ------------------------------------------------------------------------------------------ |
| زبان/اجرا   | TypeScript روی Node.js ≥ 22 (type-stripping، بدون بیلد)                                    |
| پلتفرم‌ها   | تلگرام (`api.telegram.org`) + بله (`tapi.bale.ai`) — API سازگار [1](https://docs.bale.ai/) |
| OCR         | اولویت: `POST /vision/bill/read` سرویس بینایی Xennic؛ جایگزین: OCR عمومی + استخراج regex   |
| موتور تعرفه | جداول ضریب‌محور ۱۴۰۵ (هزینه تأمین: ۱۳٬۲۵۶ ریال/kWh)                                        |
| تحلیل       | موتور قاعده‌محور (الگو/پله/اوج‌بار) + LLM اختیاری (سازگار با OpenAI)                       |
| گزارش       | قالب HTML/RTL → PDF (pdfmake با فونت وزیرمتن)                                              |
| ذخیره‌سازی  | SQLite محلی برای نشست‌ها و درخواست‌های مشاوره (بدون وابستگی)                               |
| استقرار     | Docker / PM2 / اجرای مستقیم                                                                |
