# ۰۸ — امنیت، حریم خصوصی و بهره‌برداری

## ۱. طبقه‌بندی داده

| داده | حساسیت | نگهداری |
|------|:---:|---------|
| فایل خام قبض (عکس/PDF) | 🔴 بالا (PII: نام، آدرس، شناسه‌ها) | فقط حافظه موقت؛ حذف پس از پردازش؛ **هرگز** در git یا ذخیره‌سازی پایدار |
| متن OCR خام (`rawText`) | 🔴 بالا | حداکثر ۲۴ ساعت در store محلی، سپس پاک‌سازی |
| فیلدهای ساختاریافته قبض | 🟡 متوسط | برای تاریخچه تحلیل همان کاربر (opt-out با /delete) |
| شماره تلفن درخواست مشاوره | 🔴 بالا | تا بسته‌شدن درخواست + ۳۰ روز بایگانی؛ رمز در حال سکون |
| شناسه چت/نام کاربری پلتفرم | 🟡 متوسط | تا /delete |
| گزارش PDF تولیدشده | 🟡 | کش ۱۰ دقیقه؛ پس از ارسال حذف از دیسک |

## ۲. الزامات پیاده‌سازی

- **حداقل‌سازی:** فقط فیلدهای لازم ذخیره می‌شود؛ شناسه پرداخت همیشه ماسک می‌شود (`221754***1024`) در لاگ و اعلان ادمین.
- **رمزنگاری در سکون:** پایگاه SQLite با کلید از env (`STORE_ENC_KEY`) برای ستون‌های PII (AES-256-GCM از `node:crypto`). در نبود کلید، ذخیره PII غیرفعال و فقط آمار نگهداری می‌شود.
- **در ترانزیت:** همه فراخوانی‌ها HTTPS؛ TLS سیستمی.
- **توکن‌ها:** فقط از env؛ هیچ توکنی در کد/لاگ/کامیت. `.env` در `.gitignore` ریشه مستثنا نیست.
- **اعتبارسنجی ورودی:** سقف حجم ۱۰MB، allow-list اکستنشن/MIME، رد فایل‌های با امضای ناسازگار (magic bytes).
- **محدودسازی نرخ:** هر `chatId`: ۵ فایل/ساعت، ۲۰ پیام/دقیقه؛ سراسری: ۳ OCR هم‌زمان.
- **تأیید ادمین:** `ADMIN_CHAT_IDS` فقط عدد؛ هر پیام ادمینی با چک لیست سفید، وگرنه 403 + لاگ.
- **لاگ:** ساختاریافته JSON؛ هیچ PII در سطح info؛ سطح debug فقط محلی. شناسه‌ها هش‌شده.

## ۳. انطباق و حقوقی

- سلب مسئولیت ثابت در PDF و نخستین تحلیل: «مرجع نهایی، صورتحساب رسمی شرکت توزیع برق استان است».
- دکمه / حریم: کاربر می‌تواند با `/delete` همه داده‌های خود را پاک کند (Right to erase) و با `/privacy` متن سیاست را ببیند.
- داده کاربران بین دو پلتفرم تفکیک می‌شود (کلید = `platform:chatId`).

## ۴. پایداری و خطاها

| رویداد | رفتار |
|--------|-------|
| قطع long-polling | اتصال مجدد نمایی (۱s → ۳۰s سقف) + شمارنده |
| ۴۲۹ از API پلتفرم | رعایت `retry_after` |
| خطای vision-service | fallback به مسیر OCR محلی/دستی + ثبت متریک `bill_ocr_fallback_total` |
| پر شدن دیسک موقت | پاک‌سازی خودکار فایل‌های > ۱ ساعت |
| کرش | PM2/Docker `restart: always`؛ state نشست‌ها قابل بازسازی از store |
