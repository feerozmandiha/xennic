# ۰۷ — گزارش PDF و جریان مشاوره

## ۱. گزارش PDF

### ۱.۱ مشخصات فنی

| ویژگی             | انتخاب                                                                                                                    |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| موتور             | pdfmake (اختیاری، بارگذاری پویا) — نیازمند فونت فارسی وزیرمتن/ایران‌سنس از مسیر `REPORT_FONT_PATH` (TTF)                  |
| جایگزین بدون فونت | گزارش HTML خودکفا (RTL + استایل چاپ) که به‌صورت فایل `.html` ارسال می‌شود؛ کاربر با هر مرورگری می‌تواند «Print → PDF» کند |
| اندازه صفحه       | A4 عمودی، حاشیه ۱۲mm                                                                                                      |
| جهت               | RTL کامل (`rtl: true`)                                                                                                    |
| نام فایل          | `گزارش-قبض-{billId                                                                                                        | کد۶رقمی}-{1405-04-28}.pdf` |
| سقف اجرا          | تولید < ۳ ثانیه                                                                                                           |

### ۱.۲ ساختار گزارش (۷ بخش)

1. **سربرگ** — نام/لوگوی کسب‌وکار (اختیاری `REPORT_BRAND_NAME`)، شماره گزارش یکتا (۸ نویسی)، تاریخ شمسی تولید، «تحلیل بر اساس تعرفه ۱۴۰۵ توانیر».
2. **اطلاعات قبض** — جدول دو‌ستونی تمام فیلدهای استخراج‌شده (همان جدول چت + موارد کم‌اهمیت‌تر مثل آدرس و کد پستی). فیلدهای ⚠️دار با رنگ زرد.
3. **جدول پلکانی محاسبه** — ستون‌ها: پله | بازه kWh | مصرف | نرخ (ریال/kWh) | مبلغ (ریال) + سطر جمع.
4. **صورت‌حساب** — ردیف‌های بهای انرژی، تبصره ۱۴، عوارض، ارزش افزوده، بیمه، آئونمان، **جمع کل** — ستون «روی قبض» در کنار «محاسبه ربات» و ستون انحراف.
5. **تحلیل** — جایگاه الگو (نمودار میله‌ای ساده از مصرف در برابر الگو)، نرخ مؤثر، جریمه/پاداش اوج‌بار، روایت هوشمند (در صورت فعال بودن LLM).
6. **توصیه‌ها** — جدول اولویت‌دار با برآورد صرفه‌جویی سالانه.
7. **پانوشت** — سلب مسئولیت («محاسبات جنبه اطلاع‌رسانی دارد؛ مرجع نهایی صورتحساب شرکت توزیع است»)، راه‌های تماس، QR حاوی `reportId` برای استعلام (فاز ۲).

### ۱.۳ دکمه در چت

```
[ 🖨 چاپ گزارش PDF ]  [ 🎧 درخواست مشاوره ]  [ 🔄 قبض جدید ]
```

کلیک روی «چاپ گزارش PDF» → اگر گزارش قبلاً تولید شده (کش ۱۰ دقیقه‌ای) همان فایل، وگرنه تولید تازه → `sendDocument` با کپشن خلاصه ۲ خطی.

## ۲. جریان مشاوره

### ۲.۱ مدل داده درخواست

```ts
interface ConsultationRequest {
  id: string; // 6-char, e.g. A1B2C3 (prefix # در نمایش)
  platform: 'telegram' | 'bale';
  chatId: string;
  userName?: string;
  channel: 'pv' | 'call';
  phone?: string; // E.164/local 09xxxxxxxxx — فقط مسیر call
  preferredWindow?: 'morning' | 'noon' | 'evening';
  message?: string; // فقط مسیر pv
  billSummary: {
    // خلاصه پرونده (نه کل داده شخصی)
    billId?: string;
    tariffType?: string;
    zone?: string;
    consumptionKwh?: number;
    monthlyAvgKwh?: number;
    relativeToPattern?: number;
    totalRials?: number;
    topIssue?: string; // مثال: «۲٫۸ برابر الگو — پله ۵×C»
  };
  status: 'open' | 'contacted' | 'closed';
  createdAt: string; // ISO
}
```

### ۲.۲ مسیر پیام خصوصی (PV)

```
کاربر: دکمه «💬 پیام خصوصی»
ربات:  «لطفاً سؤال یا موضوع مشاوره خود را در یک پیام بنویسید.»
ربات:  «نام شما؟ (قابل‌ویرایش با /cancel)»
کاربر: متن + نام
ربات:  ثبت → پیام «✅ درخواست #A1B2C3 ثبت شد. کارشناس ما حداکثر تا ۲۴ ساعت
       آینده در همین گفتگو پاسخ می‌دهد.»
→ اعلان ادمین: خلاصه پرونده + متن + دکمه‌های [پاسخ ↩️] [بستن ✔️]
```

### ۲.۳ مسیر تماس تلفنی

```
کاربر: دکمه «📞 تماس تلفنی»
ربات:  «شماره تماس را ارسال کنید:» + دکمه [📱 ارسال شماره من] (request_contact)
کاربر: شماره (اشتراک یا تایپ) → اعتبارسنجی ^0?9\d{9}$ → نرمال به 09xxxxxxxxx
ربات:  «بازه زمانی ترجیحی؟» [🌅 صبح ۹–۱۲] [☀️ ظهر ۱۲–۱۵] [🌇 عصر ۱۵–۱۸]
ربات:  ثبت → «✅ درخواست #A1B2C3 ثبت شد. در بازه «صبح» با شما تماس می‌گیریم.»
→ اعلان ادمین: شماره + بازه + خلاصه پرونده + دکمه‌ها
```

> در بله چنانچه `request_contact` در دسترس نباشد، فقط مسیر تایپ شماره فعال می‌ماند (ماتریس قابلیت، سند ۰۳).

### ۲.۴ اعلان و پیگیری سمت ادمین

- اعلان به همه شناسه‌های `ADMIN_CHAT_IDS` (جدا با کاما) با پیام یکسان + خلاصه پرونده.
- هر ادمین: `/requests` → فهرست باز (دکمه‌ای، صفحه‌بندی ۵تایی) → انتخاب → جزئیات + دکمه‌های [تماس گرفتم 📞] [بستن ✔️] [لغو ❌].
- کاربر: `/status` → وضعیت آخرین درخواست خود.
- SLA نمایشی: PV تا ۲۴ ساعت، تماس تا ۴۸ ساعت کاری (قابل تنظیم).

### ۲.۵ ضد‌اسپم مشاوره

- هر کاربر حداکثر ۳ درخواست باز؛ بیش از آن → پیام «درخواست قبلی شما در حال پیگیری است».
- حداقل فاصله ۱۰ دقیقه بین دو درخواست همان کاربر.
