## ۱. معرفی

این سند **قراردادهای نام‌گذاری همه موجودیت‌های SMOS** را تعریف می‌کند.
نام‌گذاری یکنواخت شرط ضروری برای قابلیت جستجو، پردازش خودکار و هماهنگی بین انسان و Agent است.

### دامنه

- شناسه اسناد (Document IDs)
- نام فایل‌ها (File Names)
- نام دایرکتوری‌ها (Directory Names)
- شناسه موجودیت‌ها (Entity IDs): ADR, CR, KPI, ...
- کلیدهای فراداده (Metadata Keys) — طبق [GOV-005](./05-metadata.md)

---

## ۲. شناسه اسناد (Document IDs)

### ۲.۱ قالب

```
MODULE-NNN
```

| بخش        | توضیح                        | مثال                 |
| ---------- | ---------------------------- | -------------------- |
| **MODULE** | پیشوند سه یا چهارحرفی ماژول  | `ARCH`, `GOV`, `CON` |
| **-**      | خط تیره                      | `-`                  |
| **NNN**    | شماره سه‌رقمی با صفر پیش‌فرض | `000`, `030`, `101`  |

### ۲.۲ ثبات پیشوند ماژول‌ها

| پیشوند | ماژول        | مثال       |
| ------ | ------------ | ---------- |
| CON    | قانون اساسی  | CON-000    |
| ARCH   | معماری       | ARCH-010   |
| GOV    | حکمرانی      | GOV-001    |
| CAM    | کمپین        | CAM-001    |
| PLAT   | پلتفرم       | PLAT-001   |
| BRD    | برند         | BRD-001    |
| EDT    | تحریریه      | EDT-001    |
| AST    | دارایی       | AST-001    |
| AUT    | خودکارسازی   | AUT-001    |
| PRM    | پرامپت       | PRM-001    |
| AI     | عامل هوش     | AI-001     |
| KNW    | دانش         | KNW-001    |
| OPS    | عملیات       | OPS-001    |
| REP    | گزارش        | REP-001    |
| MET    | سنجه         | MET-001    |
| REF    | مرجع         | REF-001    |
| TRN    | آموزش        | TRN-001    |
| ARC    | بایگانی      | ARC-001    |
| DEPLOY | استقرار      | DEPLOY-001 |
| ADR    | تصمیم معماری | ADR-001    |

### ۲.۳ قواعد شماره‌گذاری

- شماره‌ها ترتیبی و منحصربه‌فرد در هر ماژول هستند
- شماره‌های ۰۰۰–۰۹۹ رزرو: اسناد پایه و نمایه ماژول
- شماره‌های ۱۰۰–۹۹۹: اسناد محتوایی
- شماره سند حذف‌شده هرگز به سند دیگر اختصاص نمی‌یابد
- شماره ADRها سراسری (cross-module) و ترتیبی است — ARCH-034

## ۳. نام‌گذاری فایل‌ها (File Names)

### ۳.۱ قالب

```
NN-slug-name.md
```

| بخش           | توضیح                              | مثال                    |
| ------------- | ---------------------------------- | ----------------------- |
| **NN**        | شماره دو رقمی ترتیبی               | `00`, `01`, `03`        |
| **-**         | خط تیره جداکننده                   | `-`                     |
| **slug-name** | نام انگلیسی با حروف کوچک و خط تیره | `architecture-overview` |
| **.**         | نقطه                               | `.`                     |
| **md**        | پسوند Markdown                     | `.md`                   |

**مثال‌ها:**

- `00-architecture-overview.md`
- `03-glossary.md`
- `01-documentation-standards.md`

### ۳.۲ قواعد

- فقط حروف کوچک a-z، اعداد ۰-۹ و خط تیره `-`
- حداکثر ۵۰ کاراکتر برای slug
- slug توصیفی، منحصربه‌فرد در دایرکتوری ماژول
- از کلمات اختصاری در slug استفاده نکنید (مگر در شناسه)
- تطابق بین شماره فایل و شماره شناسه سند ضروری نیست ولی توصیه می‌شود

---

## ۴. نام‌گذاری دایرکتوری‌ها (Directory Names)

### ۴.۱ قالب

```
NN-MODULE-NAME/
```

| بخش             | توضیح                          | مثال                         |
| --------------- | ------------------------------ | ---------------------------- |
| **NN**          | شماره دو رقمی ترتیبی           | `00`, `10`, `80`             |
| **-**           | خط تیره                        | `-`                          |
| **MODULE-NAME** | نام انگلیسی ماژول با حروف بزرگ | `ARCHITECTURE`, `GOVERNANCE` |

**مثال‌ها:**

- `00-ARCHITECTURE/`
- `10-GOVERNANCE/`
- `80-TRAINING/`

### ۴.۲ قواعد

- نام ماژول SNAKE_UPPER_CASE
- شماره‌گذاری با پرش ۱۰ واحدی (۰۰, ۱۰, ۲۰, ...) برای امکان درج بعدی
- هیچ دایرکتوری دیگری در root اسناد مجاز نیست

## ۵. شناسه موجودیت‌ها (Entity Identifiers)

| موجودیت        | قالب          | مثال           |
| -------------- | ------------- | -------------- |
| ADR            | `ADR-NNN`     | `ADR-028`      |
| Change Request | `CR-NNN`      | `CR-001`       |
| Decision       | `DEC-XXX-NNN` | `DEC-ARCH-001` |
| KPI            | `KPI-NNN`     | `KPI-001`      |
| Rule           | `GOV-XXX-NN`  | `GOV-001-01`   |
| Layer          | `L-NN`        | `L-20`         |
| Role           | `R-NN`        | `R-01`         |

---

## ۶. قواعد عمومی

| قاعده      | توضیح                                                                  |
| ---------- | ---------------------------------------------------------------------- |
| GOV-003-01 | هر موجودیت SMOS دقیقاً یک شناسه دارد                                   |
| GOV-003-02 | شناسه‌ها case-sensitive و همیشه大写 (uppercase) هستند                  |
| GOV-003-03 | شناسه موجودیت‌های حذف‌شده هرگز به موجودیت دیگر داده نمی‌شود            |
| GOV-003-04 | slug فایل‌ها از دایرکتوری ماژول پیروی می‌کند                           |
| GOV-003-05 | از نویسه‌های خاص (فاصله، زیرخط، نویسه فارسی) در نام فایل استفاده نکنید |
| GOV-003-06 | فایل index (مانند README) فقط در ریشه `docs/` مجاز است                 |

---

## ۷. تطابق

- نگهبان (Custodian) هر ماژول مسئول تطابق نام‌گذاری اسناد ماژول خود است
- فایل‌های جدید باید پیش از ایجاد از نظر نام‌گذاری تأیید شوند
- اسناد با نام غیرمطابق باید در اولین بازبینی اصلاح شوند
- تغییر نام سند فقط با Change Request امکان‌پذیر است
