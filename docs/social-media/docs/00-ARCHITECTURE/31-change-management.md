## ۳. فرایند مدیریت تغییر (Change Management Process)

```
┌──────────────┐
│  Change      │
│  Request     │  ← ثبت درخواست تغییر
└──────┬───────┘
       ▼
┌──────────────┐
│  Impact      │
│  Analysis    │  ← تحلیل تأثیر بر سایر اجزا
└──────┬───────┘
       ▼
┌──────────────┐
│  Review      │  ← بازبینی توسط Reviewer
└──────┬───────┘
       ▼
┌──────────────┐
│  Approval    │  ← تأیید توسط Approver
└──────┬───────┘
       │
  ┌────┴────┐
  │         │
  ▼         ▼
Approved  Rejected
  │         │
  ▼         ▼
┌──────────┐  ┌──────────┐
│Implement │  │  Close   │
└─────┬────┘  └──────────┘
      ▼
┌──────────┐
│ Validate │  ← اعتبارسنجی اجرا
└─────┬────┘
      ▼
┌──────────┐
│ Version  │  ← ثبت نسخه جدید
└─────┬────┘
      ▼
┌──────────┐
│Communicate│  ← اعلام به ذی‌نفعان
└─────┬────┘
      ▼
┌──────────┐
│ Rollback │  ← آماده‌باش بازگشت
│ Plan     │
└─────┬────┘
      ▼
┌──────────┐
│  Close   │  ← بستن تغییر
└──────────┘
```

### شرح مراحل

| مرحله               | مسئول            | خروجی               | حداکثر زمان          |
| ------------------- | ---------------- | ------------------- | -------------------- |
| **Change Request**  | هر کس            | CR Form تکمیل‌شده   | —                    |
| **Impact Analysis** | Maintainer       | گزارش تحلیل تأثیر   | ۲۴ ساعت              |
| **Review**          | Reviewer         | گزارش بازبینی       | ۲۴ ساعت              |
| **Approval**        | Approver         | تصمیم تأیید/رد      | ۴۸ ساعت              |
| **Implementation**  | Maintainer       | تغییر اجراشده       | متغیر                |
| **Validation**      | Reviewer + Owner | گزارش اعتبارسنجی    | ۲۴ ساعت              |
| **Versioning**      | Maintainer       | نسخه جدید ثبت‌شده   | همزمان               |
| **Communication**   | Custodian        | اعلامیه به ذی‌نفعان | ۴ ساعت               |
| **Rollback Plan**   | Maintainer       | مستند بازگشت        | همراه Implementation |
| **Closure**         | Owner            | CR بسته‌شده         | پس از تأیید          |

### فرم Change Request

| فیلد          | توضیح                                               |
| ------------- | --------------------------------------------------- |
| CR-ID         | شناسه یکتای تغییر                                   |
| Title         | عنوان تغییر                                         |
| Type          | strategic / architectural / operational / emergency |
| Scope         | ماژول(های) affected                                 |
| Requestor     | درخواست‌دهنده                                       |
| Rationale     | دلیل تغییر                                          |
| Impact        | ماژول‌های متأثر                                     |
| Risk Level    | 1-5                                                 |
| Proposed Date | تاریخ پیشنهادی                                      |
| Attachments   | ADR, تحلیل, منابع                                   |

## ۵. حاکمیت اسناد (Document Governance)

### چرخه حیات سند

```
                    ┌──────────┐
                    │ Proposal │  ← پیشنهاد سند جدید
                    └────┬─────┘
                         ▼
                    ┌──────────┐
                    │  Draft   │  ← پیش‌نویس
                    └────┬─────┘
                         ▼
                    ┌──────────┐
                    │  Review  │  ← بازبینی
                    └────┬─────┘
                         │
                    ┌────┴────┐
                    │         │
                    ▼         ▼
              ┌─────────┐ ┌──────────┐
              │Approved │ │ Rejected │
              └────┬────┘ └──────────┘
                   │
                   ▼
              ┌──────────┐
              │ Published│  ← منتشرشده
              └────┬─────┘
                   │
              ┌────┴────┐
              │         │
              ▼         ▼
        ┌─────────┐ ┌──────────┐
        │Deprecated│ │Superseded│  ← منسوخ / جایگزین
        └────┬────┘ └────┬─────┘
             │           │
             └────┬──────┘
                  ▼
             ┌──────────┐
             │ Archived │  ← بایگانی
             └────┬─────┘
                  │
             ┌────┴────┐
             │         │
             ▼         ▼
        ┌─────────┐ ┌──────────┐
        │  Kept   │ │  Deleted │  ← نگهداری / حذف
        └─────────┘ └──────────┘
```

### قواعد گذار (Transition Rules)

| از             | به         | شرط                                 | مجوز       |
| -------------- | ---------- | ----------------------------------- | ---------- |
| **Proposal**   | Draft      | تأیید Owner                         | Owner      |
| **Draft**      | Review     | تکمیل محتوا                         | Maintainer |
| **Review**     | Approved   | تأیید Reviewer                      | Reviewer   |
| **Review**     | Rejected   | رد توسط Reviewer                    | Reviewer   |
| **Approved**   | Published  | تأیید نهایی                         | Approver   |
| **Rejected**   | Draft      | اصلاح و ارسال مجدد                  | Maintainer |
| **Published**  | Deprecated | تصمیم Owner + ۳۰ روز اطلاع          | Owner      |
| **Published**  | Superseded | سند جدید جایگزین                    | Approver   |
| **Deprecated** | Archived   | ۱ سال از Deprecated                 | Custodian  |
| **Superseded** | Archived   | ۶ ماه از Superseded                 | Custodian  |
| **Archived**   | Deleted    | ۵ سال از Archived + تأیید مدیر ارشد | مدیر ارشد  |
| **Archived**   | Kept       | نگهداری دائمی                       | Custodian  |

### قواعد اضافی

1. سند در وضعیت `Draft` برای Agentها قابل دسترسی نیست
2. سند در وضعیت `Review` فقط با برچسب `DRAFT` برای Agent قابل دسترسی است
3. سند `Published` منبع حقیقت واحد محسوب می‌شود
4. سند `Superseded` باید به سند جایگزین لینک دهد
5. سند `Deprecated` پس از ۱ سال به `Archived` منتقل می‌شود
6. سند `Deleted` فقط با مجوز مدیر ارشد قابل حذف است
7. سند `Archived` هرگز ویرایش نمی‌شود

## ۶. نسخه‌بندی اسناد

| نوع تغییر            | بخش نسخه  | مثال          |
| -------------------- | --------- | ------------- |
| اصلاح جزئی (تایپو)   | PATCH     | ۱.۰.۰ → ۱.۰.۱ |
| افزودن بخش جدید      | MINOR     | ۱.۰.۰ → ۱.۱.۰ |
| بازنویسی کامل        | MAJOR     | ۱.۰.۰ → ۲.۰.۰ |
| جایگزینی با سند جدید | SUPERSEDE | —             |

### Change Log

هر سند باید یک بخش Change Log در انتهای خود داشته باشد:

```markdown
## تغییرات

| نسخه  | تاریخ      | تغییر            | توسط |
| ----- | ---------- | ---------------- | ---- |
| ۱.۰.۱ | 2026-07-01 | اصلاح تایپوگرافی | ...  |
| ۱.۰.۰ | 2026-06-26 | انتشار اولیه     | ...  |
```
