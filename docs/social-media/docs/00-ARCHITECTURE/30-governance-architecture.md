## ۱. معرفی

این سند **معماری حکمرانی سازمانی** SMOS را تعریف می‌کند.
حکمرانی تعیین می‌کند که چه کسی چه چیزی را مالک است، چه اختیاری دارد، چگونه تصمیم‌گیری می‌کند و چگونه پاسخگو است.
هیچ چیزی در SMOS بدون حکمرانی وجود ندارد.

## ۴. مدل مالکیت (Ownership Model)

هر موجودیت SMOS دارای ۶ نقش مالکیتی است:

| نقش                        | مسئولیت                     | انتصاب    |
| -------------------------- | --------------------------- | --------- |
| **Owner (مالک)**           | پاسخگویی نهایی برای موجودیت | مدیر ارشد |
| **Custodian (نگهبان)**     | مدیریت روزمره و نگهداری     | Owner     |
| **Maintainer (نگهدارنده)** | به‌روزرسانی و اصلاحات فنی   | Custodian |
| **Reviewer (بازبین)**      | بازبینی تغییرات پیشنهادی    | Owner     |
| **Approver (تأییدکننده)**  | تأیید نهایی تغییرات         | Owner     |
| **Consumer (مصرف‌کننده)**  | استفاده از موجودیت          | سیستم     |

## ۶. چارچوب تصمیمات (Decision Framework)

### انواع تصمیمات

| نوع           | دامنه         | Frequency | Owner           | سطح تأیید    |
| ------------- | ------------- | --------- | --------------- | ------------ |
| **استراتژیک** | کل سازمان     | سالانه    | مدیر ارشد       | هیئت مدیره   |
| **معماری**    | کل سیستم      | فصلی      | معمار سیستم     | مدیر ارشد    |
| **عملیاتی**   | عملیات روزانه | روزانه    | اپراتور         | مدیر         |
| **تحریریه**   | محتوا         | روزانه    | مدیر محتوا      | مدیر تحریریه |
| **پلتفرم**    | یک پلتفرم     | هفتگی     | مدیر پلتفرم     | مدیر رسانه   |
| **برند**      | هویت برند     | فصلی      | مدیر برند       | مدیر ارشد    |
| **AI**        | Agentها       | ماهانه    | مهندس AI        | مدیر AI      |
| **اتوماسیون** | Workflowها    | ماهانه    | مهندس اتوماسیون | معمار سیستم  |
| **اضطراری**   | بحران         | لحظه‌ای   | مدیر رسانه      | مدیر ارشد    |

### جزئیات هر نوع تصمیم

#### Strategic Decisions

| فیلد                  | مقدار                                             |
| --------------------- | ------------------------------------------------- |
| **Owner**             | مدیر ارشد (Media Director)                        |

| **Required Evidence** | تحلیل بازار, گزارش عملکرد سالانه, پیش‌بینی ۳ ساله |
| **Escalation Path**   | هیئت مدیره → سهامداران                            |
| **مثال**              | ورود به پلتفرم جدید, تغییر مأموریت برند           |

## ۷. سلسله‌مراتب اختیار (Authority Hierarchy)

```
CON-000  قانون اساسی
  │  ← بالاترین مرجع
  ▼
ARCH-*  معماری
  │  ← تصمیمات ساختاری
  ▼
GOV-*  حکمرانی
  │  ← قواعد و استانداردها
  ▼
POLICIES  خط‌مشی‌ها
  │  ← اجرای استانداردها
  ▼
PROCEDURES  رویه‌ها
  │  ← دستورالعمل‌های اجرایی
  ▼
ACTIONS  اقدامات
     ← اجرا توسط انسان یا Agent
```

### قواعد سلسله‌مراتب

1. هر سطح تابع سطح بالاتر است
2. تصمیمات سطح بالاتر override کننده سطوح پایین‌تر است
3. سطوح پایین‌تر نمی‌توانند قواعد سطوح بالاتر را نقض کنند
4. در شرایط اضطراری، سطح L5 می‌تواند سلسله‌مراتب را دور بزند
5. دور زدن سلسله‌مراتب باید مستند و در ADR ثبت شود
