## ۱. Purpose — هدف

این سند راهنمای عملیات روزانه مدیریت شبکه‌های اجتماعی Xennic است. هر آنچه یک اپراتور شبکه اجتماعی برای انتشار, تعامل, پایش و گزارش‌دهی نیاز دارد در این سند تعریف شده است.

این سند معماری نیست — دستورالعمل اجرای روزانه است.

## ۴. Daily Posting Workflow — جریان کار انتشار روزانه

### مراحل

```
بررسی تقویم → آماده‌سازی محتوا → بازبینی نهایی → انتشار → تأیید انتشار → پایش تعامل
```

### چک‌لیست انتشار روزانه

- [ ] بررسی تقویم تحریریه برای محتوای امروز
- [ ] دریافت محتوای تأییدشده از مدیر تولید
- [ ] تطبیق محتوا با فرمت پلتفرم هدف
- [ ] بازبینی نهایی (املایی, لینک‌ها, هشتگ‌ها)
- [ ] انتشار در زمان تعیین‌شده
- [ ] تأیید انتشار صحیح (بررسی زنده)
- [ ] ثبت لینک انتشار در تقویم
- [ ] شروع پایش تعامل (۳۰ دقیقه اول حیاتی)

## ۶. Content Scheduling Procedures — رویه‌های زمان‌بندی انتشار

### ابزار زمان‌بندی

| مرحله        | اقدام                     | مسئول      | مهلت           |
| ------------ | ------------------------- | ---------- | -------------- |
| ثبت در تقویم | درج محتوا + زمان + پلتفرم | مدیر تولید | شنبه           |
| آماده‌سازی   | تطبیق فرمت + بارگذاری     | مدیر جوامع | ۱ روز قبل      |
| بازبینی      | بررسی نهایی قبل از انتشار | ویراستار   | ۴ ساعت قبل     |
| انتشار       | اجرای زمان‌بندی           | مدیر جوامع | زمان تعیین‌شده |

### قوانین زمان‌بندی

1. محتوا حداقل ۲۴ ساعت قبل از انتشار آماده باشد
2. محتوای حساس (بحران, رویداد) با تأیید مدیر عملیات منتشر شود
3. محتوای اتوماتیک فقط برای پست‌های از پیش تأییدشده
4. در صورت تداخل, اولویت با محتوای فوری (newsjacking)
5. محتوای Evergreen می‌تواند در هر زمانی منتشر شود

## ۷. Platform Compliance Checks — چک‌لیست انطباق پلتفرمی

### قبل از انتشار

- [ ] رعایت حداکثر طول محتوا برای پلتفرم
- [ ] استفاده از فرمت تصویر/ویدئوی صحیح
- [ ] رعایت محدودیت تعداد هشتگ
- [ ] عدم استفاده از لینک‌های ممنوع (بعضی پلتفرم‌ها)
- [ ] رعایت قوانین محتوایی هر پلتفرم
- [ ] عدم نقض کپی‌رایت
- [ ] عدم استفاده از محتوای حساس بدون مجوز
- [ ] بررسی presence محتوای مشابه در پلتفرم

### بعد از انتشار

- [ ] تأیید انتشار صحیح (بررسی زنده)
- [ ] بررسی نمایش صحیح در دستگاه‌های مختلف
- [ ] بررسی عملکرد لینک‌ها
- [ ] ثبت شماره انتشار در تقویم

### اولویت‌بندی تعاملات

| ------------- | ---------------- | ---------- | ---------- |

| اسپم          | ≤۲۴ ساعت         | مدیر جوامع | حذف/گزارش  |

### چک‌لیست پاسخ‌دهی

- [ ] شناسایی نوع تعامل (سؤال, شکایت, تعریف, انتقاد)
- [ ] بررسی سابقه تعامل با کاربر
- [ ] انتخاب الگوی پاسخ مناسب
- [ ] شخصی‌سازی پاسخ (عدم استفاده از رباتیک)
- [ ] تأیید انطباق پاسخ با صدای برند
- [ ] ثبت تعامل در سیستم پایش

### الگوهای پاسخ

| نوع تعامل     | الگوی پاسخ                | مثال                                       |

| شکایت         | عذرخواهی + بررسی + پیگیری | "متأسفیم, لطفاً DM ارسال کنید"             |
| انتقاد سازنده | تشکر + توضیح + بهبود      | "ممنون از بازخوردتون, حتماً بررسی می‌کنیم" |
| اسپم          | بدون پاسخ + حذف           | —                                          |

## ۹. Crisis Communication Procedures — رویه‌های ارتباط بحران

### سطوح بحران

| سطح                   | توصیف             | زمان پاسخ | مسئول تصمیم |
| --------------------- | ----------------- | --------- | ----------- |
| سطح ۱ — عادی          | شکایت منفرد       | ≤۲ ساعت   | مدیر جوامع  |
| سطح ۲ — محتاطانه      | چندین شکایت مشابه | ≤۱ ساعت   | مدیر عملیات |
| سطح ۳ — بحرانی        | بحران روابط عمومی | ≤۳۰ دقیقه | مدیریت ارشد |
| سطح ۴ — بحران سازمانی | تهدید حیات برند   | فوری      | مدیریت ارشد |

### چک‌لیست بحران

- [ ] شناسایی و مستندسازی بحران (اسکرین‌شات, لینک)
- [ ] طبقه‌بندی سطح بحران
- [ ] اطلاع‌رسانی به مدیر عملیات
- [ ] توقف انتشار خودکار (در صورت سطح ≥۲)
- [ ] تهیه پیش‌نویس بیانیه رسمی
- [ ] تأیید بیانیه توسط مدیریت ارشد
- [ ] انتشار بیانیه از طریق کانال رسمی
- [ ] پایش واکنش‌ها (هر ۱۵ دقیقه)
- [ ] مستندسازی کامل بحران
- [ ] جلسه بازبینی پس از بحران (۴۸ ساعت)

### قوانین بحران

1. **هیچ پاسخ خودسرانه‌ای در بحران داده نشود**
2. پاسخ‌ها فقط از بیانیه رسمی تأییدشده باشد
3. تعامل با رسانه‌ها فقط از طریق مدیریت ارشد
4. حذف نظرات فقط در صورت نقض قوانین, نه انتقاد
5. تمام ارتباطات مستند شود

## ۱۱. Cross-Platform Coordination — هماهنگی بین‌پلتفرمی

### قوانین هماهنگی

1. **محتوای یکسان در چند پلتفرم**: ابتدا در پلتفرم Hub (وبسایت) منتشر, سپس در سایر پلتفرم‌ها
2. **زمان‌بندی انتشار**: فاصله ≥۱ ساعت بین انتشار در پلتفرم‌های مختلف
3. **تطبیق محتوا**: هر پلتفرم نسخه اختصاصی خود را داشته باشد
4. **پیوند بین‌پلتفرمی**: ارجاع به محتوای مشابه در پلتفرم‌های دیگر

## ۱۳. Link Management — مدیریت لینک‌ها

### قوانین لینک

1. تمام لینک‌ها قبل از انتشار بررسی شوند
2. لینک‌های کوتاه‌شده فقط از ابزار رسمی شرکت
3. UTM parameters برای تمام لینک‌های خارجی
4. لینک‌های داخلی اولویت دارند
5. بررسی عملکرد لینک‌ها (هفتگی)

### الگوی UTM

```
utm_source=پلتفرم&utm_medium=social&utm_campaign=نام_کمپین&utm_content=نوع_محتوا
```

## ۱۹. Weekly & Monthly Cadence — ریتم هفتگی و ماهانه

### هفتگی
