## ۱. Purpose — هدف

این سند راهنمای عملیات روزانه مدیریت تعامل با جامعه Xennic است. هر آنچه یک مدیر جوامع برای پاسخ‌گویی به نظرات, مدیریت بحران, جمع‌آوری بازخورد و رصد احساسات نیاز دارد در این سند تعریف شده است.

این سند معماری نیست — دستورالعمل تعامل روزانه با جامعه است.

## ۳. Response Time SLAs — تعهدات زمانی پاسخ‌گویی

### جدول SLA بر اساس پلتفرم و اولویت

| پلتفرم      | اولویت بالا (بحران) | اولویت متوسط (سؤال) | اولویت پایین (نظر) |
| ----------- | ------------------- | ------------------- | ------------------ |
| اینستاگرام  | ≤۱۵ دقیقه           | ≤۲ ساعت             | ≤۲۴ ساعت           |
| لینکدین     | ≤۳۰ دقیقه           | ≤۴ ساعت             | ≤۲۴ ساعت           |
| تلگرام      | ≤۱۵ دقیقه           | ≤۱ ساعت             | ≤۱۲ ساعت           |
| بله         | ≤۳۰ دقیقه           | ≤۲ ساعت             | ≤۲۴ ساعت           |
| ایکس/توییتر | ≤۱۵ دقیقه           | ≤۲ ساعت             | ≤۱۲ ساعت           |
| وبسایت      | ≤۱ ساعت             | ≤۸ ساعت             | ≤۴۸ ساعت           |

### تعریف اولویت‌ها

| اولویت            | توضیح                                        | مثال                                     |
| ----------------- | -------------------------------------------- | ---------------------------------------- |
| **بالا (بحران)**  | تهدید اعتبار برند, شکایت جدی, بحران رسانه‌ای | شکایت عمومی, تهدید حقوقی, انتقاد شدید    |
| ** متوسط (سؤال)** | سؤال درباره محصول/سرویس, درخواست اطلاعات     | "قیمت چنده؟", "این قابلیت کی فعال میشه؟" |
| **پایین (نظر)**   | نظر مثبت, پیشنهاد, تشکر                      | "عالیه!", "ممنون از محتواتون"            |

## ۴. Comment Triage — طبقه‌بندی نظرات

### مراحل طبقه‌بندی

```
دریافت نظر → طبقه‌بندی اولیه → اولویت‌بندی → تصمیم‌گیری → پاسخ → ثبت
```

### جدول طبقه‌بندی

| نوع                | توضیح                        | اقدام                        | مسئول      |
| ------------------ | ---------------------------- | ---------------------------- | ---------- |
| **سؤال فنی**       | سؤال درباره محصول/قابلیت     | پاسخ فنی یا ارجاع به تیم فنی | مدیر جوامع |
| **سؤال عمومی**     | سؤال درباره برند/سرویس       | پاسخ استاندارد               | مدیر جوامع |
| **شکایت**          | نارضایتی از محصول/سرویس      | پاسخ همدلانه + پیگیری خصوصی  | مدیر جوامع |
| **پیشنهاد**        | ایده بهبود                   | تشکر + ثبت پیشنهاد           | مدیر جوامع |
| **نظر مثبت**       | تشکر, تعریف                  | پاسخ مثبت + قدردانی          | مدیر جوامع |
| **نظر منفی**       | انتقاد, نارضایتی             | پاسخ حرفه‌ای + پیگیری        | مدیر جوامع |
| **اسپم**           | محتوای تبلیغاتی نامرتبط      | حذف + مسدودسازی              | مدیر جوامع |
| **محتوای نامناسب** | الفاظ رکیک, تهدید, نژادپرستی | حذف + مسدودسازی + گزارش      | مدیر جوامع |
| **بحرانی**         | بحران رسانه‌ای, بحران برند   | ارجاع فوری به مدیر عملیات    | مدیر جوامع |

## ۵. Standard Response Templates — قالب‌های استاندارد پاسخ

### پاسخ مثبت (نظر تحسین‌آمیز)

> ممنون از لطف شما! 🙏 خوشحالیم که محتوای ما براتون مفید بوده. منتظر نظراتتون هستیم.

### پاسخ منفی (شکایت)

> سلام [نام], متوجه نارضایتی شما هستیم و این موضوع برای ما مهم است. لطفاً جزئیات بیشتر را از طریق [کانال خصوصی] برای ما ارسال کنید تا سریعاً پیگیری کنیم.

### پاسخ خنثی (سؤال)

> سلام [نام], ممنون از سؤالتون. [پاسخ سؤال]. اگر سؤال دیگه‌ای دارید, خوشحال می‌شیم کمک کنیم.

### پاسخ اسپم

> ⚠️ این نظر حذف شد (خلاف قوانین جامعه).

### پاسخ بحرانی

> [نام], متوجه نگرانی شما هستیم. تیم ما در حال بررسی موضوع است و در اسرع وقت پاسخ خواهد داد. لطفاً صبور باشید.

### قواعد استفاده از قالب‌ها

| قاعده     | توضیح                       |
| --------- | --------------------------- |
| شخصی‌سازی | همیشه نام مخاطب را ذکر کنید |
| صمیمیت    | لحن صمیمی ولی حرفه‌ای       |
| سرعت      | پاسخ در اسرع وقت (طبق SLA)  |
| پیگیری    | هر شکایت باید پیگیری شود    |
| ثبت       | هر پاسخ در ابزار ثبت شود    |

## ۶. Escalation Criteria — معیارهای ارجاع

### جدول ارجاع

| شرایط                   | ارجاع به         | زمان ارجاع |
| ----------------------- | ---------------- | ---------- |
| شکایت تکراری (≥۲ بار)   | مدیر تولید       | فوری       |
| بحران رسانه‌ای          | مدیر عملیات      | فوری       |
| تهدید حقوقی             | مدیر عملیات      | فوری       |
| شکایت از محصول          | تیم محصول        | ≤۱ ساعت    |
| سؤال فنی پیچیده         | تیم فنی          | ≤۲ ساعت    |
| درخواست مصاحبه رسانه‌ای | مدیر برند        | ≤۱ ساعت    |
| پیشنهاد همکاری          | استراتژیست محتوا | ≤۲۴ ساعت   |
| محتوای بحرانی (تهدید)   | مدیر عملیات      | فوری       |

### فرآیند ارجاع

```
شناسایی شرایط → ثبت در ابزار → اطلاع‌رسانی به مسئول → پیگیری تا حل → بستن تسک
```

### چک‌لیست ارجاع

- [ ] شرایط ارجاع شناسایی شده
- [ ] در ابزار مدیریت تسک ثبت شده
- [ ] مسئول مربوطه اطلاع‌رسانی شده
- [ ] جزئیات کامل (اسکرین‌شات, لینک, زمان) ضمیمه شده
- [ ] وضعیت پیگیری ثبت شده

## ۷. Crisis Communication Protocols — پروتکل‌های ارتباط بحران

### سطوح بحران

| سطح                | توضیح                        | مثال             | زمان پاسخ |
| ------------------ | ---------------------------- | ---------------- | --------- |
| **سطح ۱ — عادی**   | شکایت منفرد                  | یک مشتری ناراضی  | ≤۲ ساعت   |
| **سطح ۲ — بالا**   | شکایت گروهی یا رسانه‌ای کوچک | چند شکایت همزمان | ≤۳۰ دقیقه |
| **سطح ۳ — بحرانی** | بحران رسانه‌ای گسترده        | وایرال شدن منفی  | ≤۱۵ دقیقه |

### اقدامات بحرانی

| سطح       | اقدامات                                             |
| --------- | --------------------------------------------------- |
| **سطح ۱** | پاسخ همدلانه, پیگیری خصوصی, ثبت                     |
| **سطح ۲** | ارجاع به مدیر تولید, پیام رسمی, پیگیری فعال         |
| **سطح ۳** | ارجاع فوری به مدیر عملیات, توقف انتشار, بیانیه رسمی |

### قواعد بحرانی

| قاعده         | توضیح                                    |
| ------------- | ---------------------------------------- |
| سکوت نکنید    | هر بحران باید پاسخ داشته باشد            |
| عذرخواهی کنید | حتی اگر مقصر نیستید, عذرخواهی از ناراحتی |
| شفاف باشید    | اطلاعات دقیق و شفاف ارائه دهید           |
| پیگیری کنید   | بعد از حل بحران, پیگیری رضایت            |
| ثبت کنید      | همه مراحل بحران ثبت شود                  |

## ۸. Moderation Guidelines — راهنمای مدیریت محتوا

### قواعد مدیریت

| قاعده      | توضیح                         | اقدام               |
| ---------- | ----------------------------- | ------------------- |
| آزادی بیان | نظرات منفی سازنده مجاز است    | پاسخ حرفه‌ای        |
| حذف محتوا  | فقط در شرایط زیر              | طبق جدول زیر        |
| مسدودسازی  | فقط برای محتوای بسیار نامناسب | با تأیید مدیر تولید |
| گزارش      | محتوای غیرقانونی              | گزارش به پلتفرم     |

### شرایط حذف محتوا

| شرایط          | حذف   | توضیح                                    |
| -------------- | ----- | ---------------------------------------- |
| الفاظ رکیک     | بله   | هر الفاظ رکیک حذف شود                    |
| تهدید          | بله   | هر تهدیدی حذف و گزارش شود                |
| نژادپرستی      | بله   | هر محتوای نژادپرستی حذف و گزارش شود      |
| اطلاعات نادرست | بررسی | اگر اطلاعات نادرست درباره برند باشد, حذف |
| تبلیغ رقبا     | بله   | تبلیغ رقبا حذف شود                       |
| انتقاد سازنده  | خیر   | انتقاد سازنده باقی می‌ماند               |
| شکایت          | خیر   | شکایت باقی می‌ماند و پاسخ داده شود       |

## ۹. Hate Speech and Harassment Procedures — رویه‌های سخن نفرت‌پراکنی و آزار

### تعریف سخن نفرت‌پراکنی

| نوع            | توضیح                       | اقدام                        |
| -------------- | --------------------------- | ---------------------------- |
| نژادپرستی      | توهین بر اساس نژاد          | حذف + مسدودسازی + گزارش      |
| جنسیت‌گرایی    | توهین بر اساس جنسیت         | حذف + مسدودسازی + گزارش      |
| تهدید          | تهدید به خشونت              | حذف + مسدودسازی + گزارش فوری |
| آزار شخصی      | هدف قرار دادن افراد         | حذف + مسدودسازی + گزارش      |
| اطلاعات نادرست | انتشار اطلاعات نادرست عمومی | حذف + پاسخ اصلاحی            |

### فرآیند رسیدگی

```
شناسایی → حذف فوری → مسدودسازی کاربر → گزارش به پلتفرم → ثبت در ابزار → اطلاع‌رسانی به مدیر عملیات
```

### چک‌لیست رسیدگی

- [ ] محتوا شناسایی و مستند شده (اسکرین‌شات)
- [ ] محتوا فوراً حذف شده
- [ ] کاربر مسدود شده
- [ ] گزارش به پلتفرم ارسال شده
- [ ] در ابزار مدیریت ثبت شده
- [ ] مدیر عملیات اطلاع‌رسانی شده

## ۱۰. Spam Handling — مدیریت اسپم

### انواع اسپم

| نوع                 | توضیح                 | اقدام                   |
| ------------------- | --------------------- | ----------------------- |
| تبلیغاتی            | تبلیغ محصولات نامرتبط | حذف + مسدودسازی         |
| فیشینگ              | لینک‌های مخرب         | حذف + مسدودسازی + گزارش |
| ربات                | نظرات خودکار          | حذف + مسدودسازی         |
| تکراری              | نظرات تکراری          | حذف                     |
| کامنت فارسی نامفهوم | محتوای نامفهوم        | حذف                     |

### قواعد مدیریت اسپم

| قاعده     | توضیح                             |
| --------- | --------------------------------- |
| حذف فوری  | اسپم بلافاصله حذف شود             |
| مسدودسازی | کاربران اسپم‌فرست مسدود شوند      |
| گزارش     | اسپم به پلتفرم گزارش شود          |
| ثبت       | تعداد اسپم در گزارش هفتگی ثبت شود |

## ۱۲. Sentiment Monitoring Workflow — جریان کار رصد احساسات

### مراحل رصد

```
جمع‌آوری داده → طبقه‌بندی احساسات → تحلیل روند → گزارش → اقدام
```

### طبقه‌بندی احساسات

| احساس      | نشانه‌ها                 | اقدام                  |
| ---------- | ------------------------ | ---------------------- |
| **مثبت**   | تشکر, تعریف, رضایت       | تقویت, بازنشر, قدردانی |
| **خنثی**   | سؤال, اطلاعات, نظر عادی  | پاسخ استاندارد         |
| **منفی**   | شکایت, انتقاد, نارضایتی  | پاسخ همدلانه, پیگیری   |
| **بحرانی** | تهدید, بحران, بسیار منفی | ارجاع فوری             |

### چک‌لیست رصد روزانه

- [ ] نظرات و پیام‌های جدید بررسی شده
- [ ] احساسات کلی ثبت شده
- [ ] نظرات بحرانی شناسایی و ارجاع شده
- [ ] روند احساسات در گزارش هفتگی ثبت شده

## ۱۳. Daily Monitoring Checklist — چک‌لیست نظارت روزانه

### صبح (۰۸:۰۰-۰۹:۰۰)

- [ ] بررسی نظرات و پیام‌های جدید در همه پلتفرم‌ها
- [ ] طبقه‌بندی اولیه نظرات (بخش ۴)
- [ ] پاسخ به نظرات بحرانی و فوری
- [ ] بررسی اعلان‌های پلتفرم
- [ ] ثبت آمار اولیه روز

### ظهر (۱۲:۰۰-۱۳:۰۰)

- [ ] بررسی مجدد نظرات جدید
- [ ] پاسخ به نظرات اولویت متوسط
- [ ] بررسی وضعیت نظرات بحرانی
- [ ] به‌روزرسانی آمار روز

### عصر (۱۶:۰۰-۱۷:۰۰)

- [ ] بررسی نهایی نظرات روز
- [ ] پاسخ به نظرات باقی‌مانده
- [ ] ثبت آمار نهایی روز
- [ ] تهیه خلاصه روز (در صورت نیاز)

## ۱۵. Reporting Procedures — رویه‌های گزارش‌دهی

### گزارش روزانه (اختیاری)

| ------------- | ---------------------- |
| تعداد نظرات   | کل نظرات دریافتی       |
| تعداد پاسخ‌ها | کل نظرات پاسخ‌داده‌شده |

| پیشنهادات بهبود   | بر اساس بازخوردها  |
| برنامه هفته بعد   | اولویت‌ها          |

### گزارش ماهانه

| بخش                 | محتوا             |
| ------------------- | ----------------- |

| بینش مخاطب          | تحلیل بازخوردها   |
| پیشنهادات استراتژیک | بر اساس داده‌ها   |
| برنامه ماه آینده    | اولویت‌ها و اهداف |

## ۱۶. Handoff to Other Teams — تحویل به تیم‌های دیگر

### شرایط تحویل

| شرایط            | تحویل به         | اطلاعات همراه               |

## ۱۹. Monthly Community Strategy Review — بازبینی ماهانه استراتژی جامعه

### فرآیند بازبینی

```
جمع‌آوری داده‌ها → تحلیل عملکرد → بررسی رقبا → شناسایی فرصت‌ها → تدوین استراتژی → تصویب → اجرا
```

### جلسه بازبینی ماهانه (هفته چهارم — ۶۰ دقیقه)

**شرکت‌کنندگان:** مدیر جوامع, مدیر عملیات, استراتژیست محتوا, تحلیلگر

| بخش              | مدت      | محتوا                       |
| ---------------- | -------- | --------------------------- |
| مرور عملکرد ماه  | ۱۰ دقیقه | معیارهای اصلی ماه           |
| تحلیل احساسات    | ۱۰ دقیقه | روند احساسات مخاطبان        |
| بررسی بحران‌ها   | ۱۰ دقیقه | بحران‌های ماه و نحوه مدیریت |
| بینش مخاطب       | ۱۰ دقیقه | بازخوردها و پیشنهادات       |
| استراتژی ماه بعد | ۱۵ دقیقه | اهداف و برنامه‌ها           |
| تصمیم‌گیری       | ۵ دقیقه  | تصویب برنامه                |
