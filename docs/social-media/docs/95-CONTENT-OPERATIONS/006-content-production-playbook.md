## ۱. Purpose — هدف

این سند راهنمای عملیات روزانه تولید محتوا در Xennic است. از لحظه دریافت brief تا تحویل نهایی, هر مرحله فرآیند تولید محتوا در این سند تعریف شده است.

این سند معماری نیست — دستورالعمل اجرای روزانه تولید محتوا است.

## ۳. Production Workflow — جریان کار تولید

### مراحل اصلی

```
Brief → تحقیق → پیش‌نویس → بازبینی ویراستار → اصلاحات → بازبینی نهایی → تأیید → تحویل
```

### جدول مراحل

| مرحله            | ورودی              | خروجی               | مسئول       | حداکثر زمان |
| ---------------- | ------------------ | ------------------- | ----------- | ----------- |
| Brief            | درخواست محتوا      | brief تکمیل‌شده     | مدیر تولید  | ۱ روز       |
| تحقیق            | brief              | منابع و اطلاعات     | نویسنده     | ۱ روز       |
| پیش‌نویس         | brief + منابع      | پیش‌نویس اولیه      | نویسنده     | ۲ روز       |
| بازبینی ویراستار | پیش‌نویس           | نتیجه بازبینی       | ویراستار    | ۱ روز       |
| اصلاحات          | نتیجه بازبینی      | پیش‌نویس اصلاح‌شده  | نویسنده     | ۱ روز       |
| بازبینی نهایی    | پیش‌نویس اصلاح‌شده | تأیید/رد            | مدیر تولید  | ۰.۵ روز     |
| تأیید            | نسخه نهایی         | تأیید نهایی         | مدیر عملیات | ۰.۵ روز     |
| تحویل            | تأیید نهایی        | محتوای آماده انتشار | مدیر تولید  | ≤۲ ساعت     |

## ۴. Content Brief Creation — ایجاد brief محتوا

### فرم brief

| فیلد           | الزام   | توضیح                       | مثال                          |
| -------------- | ------- | --------------------------- | ----------------------------- |
| عنوان محتوا    | الزامی  | عنوان نهایی یا تقریبی       | "راهنمای مدیریت شبکه اجتماعی" |
| هدف محتوا      | الزامی  | آگاهی/تعامل/تبدیل/آموزش     | آگاهی                         |
| مخاطب هدف      | الزامی  | گروه مخاطب مشخص             | مدیران بازاریابی              |
| پلتفرم‌های هدف | الزامی  | پلتفرم‌های مقصد             | وبسایت, لینکدین               |
| نوع محتوا      | الزامی  | مقاله/پست/ویدئو/اینفوگرافیک | مقاله                         |
| کلمات کلیدی    | اختیاری | برای SEO                    | مدیریت شبکه اجتماعی           |
| لحن محتوا      | الزامی  | رسمی/غیررسمی/آموزشی         | آموزشی                        |
| حجم محتوا      | الزامی  | تعداد کلمات/دقیقه           | ≥۱۰۰۰ کلمه                    |
| مهلت تولید     | الزامی  | تاریخ تحویل                 | ۱۴۰۵/۰۴/۲۰                    |
| مهلت بازبینی   | الزامی  | تاریخ بازبینی               | ۱۴۰۵/۰۴/۲۲                    |
| منابع مرجع     | اختیاری | لینک‌ها و اسناد مرجع        | لینک‌ها                       |
| CTA مورد نظر   | الزامی  | اقدام مورد انتظار مخاطب     | مراجعه به وبسایت              |
| نکات کلیدی     | الزامی  | ≤۵ نکته اصلی                | ۱, ۲, ۳, ۴, ۵                 |

### چک‌لیست brief

- [ ] تمام فیلدهای الزامی تکمیل شده
- [ ] هدف محتوا واضح و قابل اندازه‌گیری
- [ ] مخاطب هدف مشخص
- [ ] مهلت‌ها واقع‌بینانه
- [ ] منابع کافی در اختیار نویسنده
- [ ] brief توسط مدیر تولید تأیید شده

### تصمیم‌نامه نوع محتوا

| هدف        | نوع محتوای پیشنهادی                  |
| ---------- | ------------------------------------ |
| آگاهی      | مقاله, اینفوگرافیک, ویدئوی کوتاه     |
| تعامل      | نظرسنجی, سؤال, محتوای تعاملی         |
| تبدیل      | مطالعه موردی, راهنمای جامع, وبینار   |
| آموزش      | آموزش گام‌به‌گام, ویدئوی آموزشی, PDF |

## ۵. Research & Sourcing — تحقیق و جمع‌آوری منابع

### منابع مجاز

| نوع منبع            | اولویت | بررسی اعتبار       |
| ------------------- | ------ | ------------------ |
| گزارش‌های رسمی صنعت | بالا   | بررسی تاریخ انتشار |
| مقالات علمی         | بالا   | بررسی نشریه معتبر  |
| اخبار معتبر         | متوسط  | بررسی چند منبع     |
| تجربه داخلی شرکت    | بالا   | تأیید مدیریت       |
| نظرات متخصصان       | متوسط  | بررسی اعتبار       |
| شبکه‌های اجتماعی    | پایین  | اعتبارسنجی         |

### منابع ممنوع

- محتوای بدون ذکر منبع
- اطلاعات قدیمی (بیش از ۲ سال)
- محتوای کپی‌رایت‌دار بدون مجوز
- اطلاعات تأییدنشده
- محتوای رقبا بدون ارجاع

### چک‌لیست تحقیق

- [ ] جمع‌آوری ≥۳ منبع معتبر
- [ ] بررسی اعتبار هر منبع
- [ ] استخراج نکات کلیدی
- [ ] ثبت منابع در brief
- [ ] شناسایی شکاف‌های اطلاعاتی
- [ ] تأیید کافی بودن منابع توسط مدیر تولید

## ۶. Writing Standards — استانداردهای نگارشی

### قوانین نگارشی

| قاعده        | توضیح                       |
| ------------ | --------------------------- |
| طول جمله     | ≤۲۵ کلمه                    |
| طول پاراگراف | ≤۵ جمله                     |
| ساختار عنوان | H2 → H3 → H4 (حداکثر ۳ سطح) |
| لیست‌ها      | حداکثر ۱۰ آیتم              |
| CTA          | حداقل ۱ CTA در هر ۳۰۰ کلمه  |
| ارجاعات      | ذکر منبع برای هر ادعا       |

### استانداردهای لحن

| پلتفرم     | لحن         | مثال                            |
| ---------- | ----------- | ------------------------------- |
| وبسایت     | رسمی-آموزشی | "در این مقاله بررسی می‌کنیم..." |
| لینکدین    | حرفه‌ای     | "نکته کلیدی برای مدیران..."     |
| اینستاگرام | صمیمی       | "یه نکته جالب براتون داریم..."  |
| تلگرام     | خبری-روان   | "خبر جدید: ..."                 |
| ایکس       | کوتاه و تیز | "نکته: ..."                     |

### ممنوعیت‌های نگارشی

- استفاده از زبان تبعیض‌آمیز
- ادعاهای بدون پشتوانه
- اطلاعات شخصی بدون اجازه
- لینک‌های شکسته
- غلط املایی و دستوری

## ۹. Internal Review Process — فرآیند بازبینی داخلی

### مراحل بازبینی

```
پیش‌نویس → بازبینی نویسنده → بازبینی ویراستار → بازبینی مدیر تولید → تأیید نهایی
```

### بازبینی نویسنده (خودبازبینی)

- [ ] بررسی املایی و دستوری
- [ ] بررسی ساختار محتوا
- [ ] بررسی انطباق با brief
- [ ] بررسی کیفیت لینک‌ها
- [ ] بررسی کیفیت تصاویر

### بازبینی ویراستار

| معیار               | توضیح           | حداقل نمره |
| ------------------- | --------------- | ---------- |
| انطباق با صدای برند | لحن و سبک       | ۹۰٪        |
| دقت اطلاعات         | صحت منابع       | ۱۰۰٪       |
| کیفیت نگارش         | روانی و خوانایی | ۸۵٪        |
| ساختار محتوا        | ترتیب و منطق    | ۸۵٪        |
| CTA                 | وضوح و اثربخشی  | ۸۰٪        |

### بازبینی مدیر تولید

- [ ] بررسی انطباق با اهداف کسب‌وکار
- [ ] بررسی کیفیت کلی
- [ ] بررسی آمادگی برای انتشار
- [ ] تصمیم نهایی (تأیید/اصلاح/رد)

## ۱۰. Revision Handling — مدیریت اصلاحات

### سطوح اصلاحات

| سطح   | توصیح            | تعداد مجاز | مسئول        | مهلت     |
| ----- | ---------------- | ---------- | ------------ | -------- |
| سطح ۱ | املایی, دستوری   | ≤۵         | نویسنده      | ≤۴ ساعت  |
| سطح ۲ | ساختاری, محتوایی | ≤۳         | نویسنده      | ≤۱۲ ساعت |
| سطح ۳ | بازنویسی جزئی    | ≤۱         | نویسنده      | ≤۲۴ ساعت |
| سطح ۴ | بازنویسی کامل    | ۱ بار      | نویسنده/جدید | ≤۴۸ ساعت |

### جدول تصمیم اصلاحات

| نتیجه بازبینی    | اقدام                | تعداد بازبینی مجاز |
| ---------------- | -------------------- | ------------------ |
| تأیید بدون اصلاح | انتقال به مرحله بعد  | ۰                  |
| اصلاحات جزئی     | اصلاح + بازبینی مجدد | ≤۲                 |
| اصلاحات اساسی    | بازگشت به تولید      | ≤۱                 |
| رد محتوا         | انتخاب موضوع جایگزین | —                  |

### قوانین اصلاحات

1. **حداکثر ۳ دور بازبینی**: پس از آن, موضوع جایگزین می‌شود
2. **مستندسازی اصلاحات**: هر درخواست اصلاح ثبت شود
3. **优先级 اصلاحات**: اصلاحات P1 فوری, P2 ≤۲۴ ساعت
4. **بازبینی اصلاحات**: اصلاحات فقط توسط همان ویراستار بازبینی شود

## ۱۱. Final Approval — تأیید نهایی

### مراحل تأیید

```
تکمیل اصلاحات → بازبینی نهایی ویراستار → تأیید مدیر تولید → تأیید مدیر عملیات → آماده انتشار
```

### چک‌لیست تأیید نهایی

- [ ] تمام اصلاحات اعمال شده
- [ ] انطباق کامل با brief
- [ ] انطباق با صدای برند
- [ ] دقت اطلاعات تأیید شده
- [ ] کیفیت بصری تأیید شده
- [ ] لینک‌ها و هشتگ‌ها بررسی شده
- [ ] فرمت پلتفرم رعایت شده
- [ ] CTA واضح و مؤثر
- [ ] امضا و تأیید مدیر تولید
- [ ] امضا و تأیید مدیر عملیات (برای P1)

### جدول تصمیم تأیید

| نتیجه      | اقدام              | مسئول       |
| ---------- | ------------------ | ----------- |
| تأیید      | انتقال به انتشار   | مدیر عملیات |
| اصلاح جزئی | اصلاح سریع + تأیید | نویسنده     |
| رد         | بازگشت به تولید    | مدیر تولید  |

## ۱۲. Asset Management — مدیریت دارایی‌ها

### ساختار دایرکتوری

```
content/
├── briefs/           ← briefهای محتوا
├── drafts/           ← پیش‌نویس‌ها
├── reviewed/         ← بازبینی‌شده
├── approved/         ← تأییدشده
├── published/        ← منتشرشده
├── images/           ← تصاویر
├── videos/           ← ویدئوها
├── assets/           ← دارایی‌های بصری
└── archive/          ← بایگانی
```

### قوانین مدیریت دارایی

1. **نام‌گذاری یکپارچه**: تمام فایل‌ها طبق قرارداد نام‌گذاری
2. **بکاپ خودکار**: روزانه از دارایی‌ها بکاپ گرفته شود
3. **دسترسی کنترل‌شده**: فقط افراد مجاز به ویرایش
4. **بایگانی منظم**: دارایی‌های قدیمی بایگانی شوند

## ۱۳. File Naming Conventions — قرارداد نام‌گذاری فایل‌ها

### الگوی نام‌گذاری

```
[تاریخ]-[نوع]-[موضوع]-[نسخه].[پسوند]
```

### مثال‌ها

| نوع محتوا | الگوی نام                      | مثال                                  |
| --------- | ------------------------------ | ------------------------------------- |
| مقاله     | YYYYMM-DD-article-title-vN.md  | 2026-07-12-article-social-media-v1.md |
| تصویر     | YYYYMM-DD-img-title-vN.jpg     | 2026-07-12-img-infographic-v1.jpg     |
| ویدئو     | YYYYMM-DD-vid-title-vN.mp4     | 2026-07-12-vid-tutorial-v1.mp4        |
| brief     | YYYYMM-DD-brief-title-vN.md    | 2026-07-12-brief-campaign-v1.md       |
| پست       | YYYYMM-DD-post-platform-vN.txt | 2026-07-12-post-linkedin-v1.txt       |

### قوانین نام‌گذاری

1. **فقط حروف انگلیسی, اعداد, خط تیره و زیرخط**
2. **بدون فاصله**: از خط تیره استفاده شود
3. **تاریخ اول**: YYYYMM-DD
4. **نسخه‌بندی**: v1, v2, v3...
5. **پسوند صحیح**: با نوع فایل مطابقت داشته باشد

## ۱۴. Version Tracking — ردیابی نسخه

### جدول ردیابی نسخه

| نسخه | تاریخ | تغییرات          | مسئول      | وضعیت     |
| ---- | ----- | ---------------- | ---------- | --------- |
| v1   | تاریخ | ایجاد اولیه      | نویسنده    | Draft     |
| v2   | تاریخ | اصلاحات ویراستار | نویسنده    | In Review |
| v3   | تاریخ | اصلاحات نهایی    | نویسنده    | Final     |
| v4   | تاریخ | تغییرات مدیریتی  | مدیر تولید | Approved  |

### قوانین ردیابی

1. **هر تغییر نسخه جدید**: حتی تغییر کوچک
2. **ذخیره نسخه قبلی**: قبل از ویرایش, نسخه فعلی ذخیره شود
3. **توضیح تغییرات**: هر نسخه باید توضیح داشته باشد
4. **نسخه نهایی مشخص**: نسخه تأییدشده با برچسب "FINAL" مشخص شود

## ۱۷. Handoff Procedures — رویه‌های تحویل بین نقش‌ها

### تحویل‌ها

| از                       | به                  | محتوای تحویل    | فرمت       | مسئول ثبت |
| ------------------------ | ------------------- | --------------- | ---------- | --------- |
| مدیر تولید → نویسنده     | brief + منابع       | فرم brief تکمیل | مدیر تولید |
| نویسنده → ویراستار       | پیش‌نویس + منابع    | فایل متنی       | نویسنده    |
| ویراستار → نویسنده       | نتیجه بازبینی       | فایل با نظرات   | ویراستار   |
| نویسنده → مدیر تولید     | پیش‌نویس اصلاح‌شده  | فایل نهایی      | نویسنده    |
| مدیر تولید → مدیر عملیات | نسخه نهایی          | فایل + brief    | مدیر تولید |
| مدیر تولید → طراح        | محتوای بصری + brief | فرم brief بصری  | مدیر تولید |
| طراح → مدیر تولید        | دارایی بصری         | فایل + مشخصات   | طراح       |

### چک‌لیست تحویل

- [ ] محتوای کامل و بدون نقص
- [ ] نام‌گذاری صحیح فایل
- [ ] مستندات همراه تحویل داده شده
- [ ] ثبت تحویل در سیستم
- [ ] اطلاع‌رسانی به گیرنده
- [ ] تأیید دریافت توسط گیرنده
