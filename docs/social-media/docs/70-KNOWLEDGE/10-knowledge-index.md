## Architectural Dependencies

### Why This Document Exists

SMOS شامل ده‌ها دانش سازمانی در خانواده‌ها و دامنه‌های مختلف است. بدون یک نمایه مرکزی:

- هر KNW-\* ساختار متفاوتی خواهد داشت
- شناسه‌های تکراری یا متضاد ایجاد می‌شوند
- وابستگی بین دانش‌ها غیرقابل ردیابی است
- نگاشت دانش به Agent و Workflow نامشخص می‌ماند
- Governance و حسابرسی دانش غیرممکن است

KNW-001 این مشکلات را با تعریف یک **چارچوب نمایه دانش سازمانی** حل می‌کند که همه KNW-\*ها از آن پیروی می‌کنند.

### Problems It Solves

1. **نبود استاندارد**: هر دانش ساختار متفاوت → یکسان‌سازی با Metadata Standard
2. **شناسه‌های پراکنده**: تداخل شناسه‌ها → Canonical Registry مرکزی
3. **وابستگی نامشخص**: زنجیره دانش‌ها نامشخص → Dependency Model با DAG
4. **نگاشت ناقص**: ارتباط دانش با Agent و Workflow نامشخص → Mapping Matrix
5. **توسعه‌ناپذیر**: اضافه‌شدن دانش جدید بدون بازطراحی → Reserved Identifier Space

### Explicit Scope

این سند فقط تعریف می‌کند:

- فلسفه و اصول نمایه دانش SMOS
- Canonical Identifier Rules
- خانواده‌ها و دامنه‌های دانش
- استاندارد فراداده و شناسه‌گذاری
- ثبت مرکزی همه دانش‌ها
- نگاشت دانش به Agent, Automation, Platform
- Dependency Registry دانش‌ها
- ماشین وضعیت و چرخه حیات در Registry
- جدول شناسه‌های رزروشده

### Explicit Non-Scope

این سند هرگز شامل موارد زیر نیست:

- محتوای دانش (در KNW-NNN)
- معماری دانش (در KNW-000)
- پیاده‌سازی Agent (در AI-\*)
- پیاده‌سازی Workflow (در AUT-\*)
- کد، اسکریپت، API
- Vendor-specific syntax
- مثال دانش

## ۱. Purpose

### جایگاه دانش در SMOS

KNW-001 نمایه مرکزی تمام دانش سازمانی SMOS است. این سند به عنوان **تک منبع حقیقت (SSOT)** برای ثبت، شناسایی و ردیابی همه اسناد KNW عمل می‌کند.

```
┌─────────────────────────────────────────────────────────┐
│                 Knowledge Architecture                     │
│  KNW-000 (معماری — SSOT معماری)                          │
└──────────────────────────┬──────────────────────────────┘
                           │ Defines
                           ▼
┌─────────────────────────────────────────────────────────┐
│                  Knowledge Index                          │
│  KNW-001 (نمایه — SSOT رجیستری — این سند)               │
├─────────────────────────────────────────────────────────┤
│  Registry · Identity · DAG · Mapping                     │
└──────────────────────────┬──────────────────────────────┘
                           │ Registers
                           ▼
┌─────────────────────────────────────────────────────────┐
│               Knowledge Base Documents                    │
│  KNW-100+ · KNW-200+ · KNW-300+ · ... · KNW-900+        │
│  (محتوای واقعی دانش)                                     │
└─────────────────────────────────────────────────────────┘
```

### سه اصل بنیادین

| اصل                                | توضیح                                  |
| ---------------------------------- | -------------------------------------- |
| **KNW-000 معماری را تعریف می‌کند** | ساختار، هویت، طبقه‌بندی، چرخه حیات     |
| **KNW-001 نمایه را نگه می‌دارد**   | ثبت مرکزی، نگاشت، شناسه‌ها، وابستگی‌ها |
| **KNW-NNN پیاده‌سازی می‌کند**      | محتوای واقعی دانش                      |

### اهداف KNW-001

1. **ایجاد زبان مشترک**: همه KNW-\*ها از یک چارچوب شناسه‌گذاری واحد پیروی می‌کنند
2. **جلوگیری از هرج‌ومرج**: شناسه‌ها، فراداده و ساختار یکسان
3. **قابلیت ردیابی**: هر دانش قابل ردیابی، حسابرسی و اشکال‌زدایی است
4. **مقیاس‌پذیری**: دانش جدید بدون بازطراحی معماری اضافه می‌شود
5. **نگاشت کامل**: ارتباط دانش با Agentها، Workflowها و پلتفرم‌ها مشخص است
6. **حکمرانی یکپارچه**: همه دانش‌ها تابع Governance یکسان هستند
