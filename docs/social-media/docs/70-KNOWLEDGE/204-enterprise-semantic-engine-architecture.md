## ۱. Purpose

KNW-203 معماری موتور معنایی سازمانی SMOS را تعریف می‌کند. این سند به عنوان **تک منبع حقیقت (SSOT)** برای تفسیر معنایی، سازگاری معنایی، واسط‌های استدلال معنایی، تفکیک دانش، نمایه‌سازی معنایی و سرویس‌های معنایی سازمانی عمل می‌کند — بدون وابستگی به فناوری، فروشنده، پایگاه داده بردار، مدل تعبیه، زبان هستی‌شناسی یا LLM.

### Why KNW-203 Exists

بدون یک معماری موتور معنایی سازمانی:

- تفسیر معنایی موجودیت‌ها و روابط دانش بدون چارچوب معماری انجام می‌شود
- سازگاری معنایی بین خانواده‌های مختلف دانش تضمین نمی‌شود
- تفکیک هویت‌های متعارف (Canonical Identity Resolution) بدون تعریف معماری ناممکن است
- نمایه‌سازی معنایی برای کشف دانش بدون معماری یکپارچه غیرممکن است
- سرویس‌های معنایی به صورت جزیره‌ای و ناسازگار پیاده‌سازی می‌شوند
- تکامل معنایی دانش بدون درک تأثیر بر سایر معانی غیرممکن است

KNW-203 این مشکلات را با تعریف یک **چارچوب معماری معنایی سازمانی** حل می‌کند که بر روی گراف دانش (KNW-202) عملیات تفسیر معنایی را تعریف می‌کند.

## ۴. Semantic Engine Philosophy

### فلسفه موتور معنایی سازمانی

SMOS موتور معنایی را به عنوان **لایه تفسیر دانش سازمانی** می‌بیند که:

1. **بر روی گراف کار می‌کند** — ورودی آن گره‌ها و یال‌های KNW-202 هستند
2. **معنا را تفسیر می‌کند** — نه ذخیره و نه پردازش — تفسیر روابط بین موجودیت‌ها
3. **چندلایه است** — هر لایه سطح مشخصی از تفسیر معنایی را ارائه می‌دهد
4. **بدون وضعیت است** — خود موتور معنایی دارای وضعیت نیست — وضعیت در گراف دانش است
5. **تکامل‌پذیر است** — لایه‌های تفسیر می‌توانند در طول زمان گسترش یابند
6. **خنثی است** — معماری به هیچ فناوری، استاندارد یا فروشنده خاصی وابسته نیست

### تمایز از سایر مؤلفه‌ها

| مؤلفه                | ویژگی                     | KNW-203                                            |
| -------------------- | ------------------------- | -------------------------------------------------- |
| KNW-201 (کامپایلر)   | تبدیل خام به ساختاریافته  | کامپایلر دانش ورودی موتور معنایی است               |
| KNW-202 (گراف)       | بازنمایی روابط            | گراف دانش داده‌ای است که موتور معنایی تفسیر می‌کند |

| AI-502 (استدلال)     | معماری استدلال هوش مصنوعی | استدلال از سرویس‌های معنایی استفاده می‌کند         |
| پایگاه داده معنایی   | ذخیره و بازیابی معنایی    | معماری — نه پیاده‌سازی                             |

## ۱۳. Semantic State Model

### ماشین وضعیت معنایی

```markdown
                    ┌──────────────┐
                    │   Defined    │
                    │ (تعریف‌شده)   │
                    └──────┬───────┘
                           │ Resolve
                           ▼
                    ┌──────────────┐
                    │  Resolved    │
                    │ (تفکیک‌شده)   │
                    └──────┬───────┘
                           │ Validate
                           ▼
                    ┌──────────────┐
                    │  Validated   │
                    │ (معتبر)      │
                    └──────┬───────┘
                           │ Activate
                           ▼
                    ┌──────────────┐
                    │   Active     │
                    │  (فعال)      │
                    └──────┬───────┘
                     ┌─────┴──────┐
                     │            │
                     ▼            ▼
               ┌──────────┐ ┌──────────┐
               │Deprecated│ │  Frozen  │
               │(منسوخ)   │ │(منجمد)   │
               └─────┬────┘ └────┬─────┘
                     │           │
                     ▼           ▼
               ┌──────────────────────┐
               │      Archived        │
               │    (بایگانی‌شده)      │
               └──────────┬───────────┘
                          │
                          ▼
               ┌──────────────────────┐
               │      Removed         │
               │    (حذف‌شده)         │
               └──────────────────────┘
```

| ------ | ---------- | ------------------------------------------------- | ------------------------ |
| SES-01 | Defined    | تعریف‌شده — تفسیر معنایی ایجاد شده اما تفکیک نشده | → SES-02                 |

| SES-05 | Deprecated | منسوخ — تفسیر معتبر نیست، نیازمند بازبینی         | → SES-07, SES-08         |
| SES-06 | Frozen     | منجمد — تفسیر غیرقابل تغییر، فقط خواندنی          | → SES-07                 |
| SES-07 | Archived   | بایگانی‌شده — غیرفعال، قابل بازیابی               | → SES-04, SES-08         |
| SES-08 | Removed    | حذف‌شده — تفسیر از موتور حذف شده است              | — (نهایی)                |

## ۲۹. Semantic Integrity Rules

### قواعد یکپارچگی معنایی

| ID      | قاعده                                 | توضیح                                                   | منبع     |
| ------- | ------------------------------------- | ------------------------------------------------------- | -------- |
| SINT-01 | هر موجودیت معنایی یک هویت متعارف دارد | هیچ موجودیتی بدون هویت معنایی یکتا مجاز نیست            | SECST-01 |
| SINT-02 | هر رابطه معنایی دارای نوع است         | هیچ رابطه‌ای بدون نوع از SER-01..10 مجاز نیست           | SECST-02 |
| SINT-03 | هر تفسیر قابل ردیابی است              | هر تفسیر باید رد کامل تا SSOT مبدأ داشته باشد           | SECST-06 |
| SINT-04 | بدون ابهام canonical                  | هر موجودیت در یک بافت یک معنای واحد دارد                | SECST-05 |
| SINT-05 | بدون مالکیت تکراری                    | هر تفسیر یک مالک دارد — دو مالک برای یک تفسیر مجاز نیست | SOR-01   |
| SINT-06 | بدون چرخه معنایی                      | وابستگی‌های معنایی یک DAG هستند                         | SCP-01   |
| SINT-07 | بدون orphan معنایی                    | هر تفسیر به حداقل یک موجودیت در گراف متصل است           | SCS-06   |
| SINT-08 | بدون تفسیر بدون بافت                  | هر تفسیر至少 یک بافت مشخص دارد                          | SCS-05   |
