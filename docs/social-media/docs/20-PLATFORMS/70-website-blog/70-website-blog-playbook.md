## Architectural Dependencies

### Why This Document Exists

هر کتابچه پلتفرم SMOS باید از PLAT-000 پیروی کند. PLAT-007 این ساختار را برای **وبسایت / Knowledge Hub** پیاده‌سازی می‌کند. وبسایت یک شبکه اجتماعی نیست — مخزن اصلی، دائمی و متعارف تمام محتوای سازمانی Xennic است.

وبسایت تنها پلتفرم SMOS است که:

- **مالکیت کامل سازمانی** دارد — وابسته به پلتفرم سوم نیست
- **SSOT انتشار** است — اولین و کامل‌ترین نسخه هر محتوا اینجا منتشر می‌شود
- **SEO-first** است — موتورهای جستجو محتوای آن را ایندکس می‌کنند
- **حافظه دائمی برند** است — هر محتوا بدون محدودیت زمان ذخیره می‌شود
- **AI-readable** است — Agentها می‌توانند محتوای آن را پردازش و استخراج کنند
- **Hub تمام پلتفرم‌ها** است — همه به اینجا ختم می‌شوند

### Problems It Solves

1. **نبود SSOT انتشار**: محتوا در پلتفرم‌های مختلف پراکنده است → وبسایت تنها مرجع معتبر
2. **عدم ماندگاری محتوا**: محتوای شبکه‌های اجتماعی پس از مدتی از دست می‌رود → ذخیره دائمی در وبسایت
3. **سئوی پراکنده**: هر پلتفرم قواعد سئوی خود را دارد → وبسایت مرکز سئوی سازمانی
4. **عدم قابلیت ایندکس ماشینی**: Agentها نمی‌توانند محتوای شبکه‌های اجتماعی را کامل پردازش کنند → وبسایت API و ساختار استاندارد دارد
5. **وابستگی به پلتفرم سوم**: بسته شدن یا تغییر خط‌مشی پلتفرم‌ها → وبسایت مالکیت کامل دارد
6. **عدم یکپارچگی دانش**: دانش در پلتفرم‌ها پراکنده است → وبسایت مخزن دانش یکپارچه

## ۱. Executive Summary

PLAT-007 کتابچه عملیاتی پلتفرم **وبسایت / Knowledge Hub** در SMOS است. وبسایت با نقش **Hub (مرکز)** و اولویت **P0 (بیشترین)** به عنوان مخزن اصلی، دائمی و متعارف تمام محتوای سازمانی Xennic عمل می‌کند.

برخلاف همه پلتفرم‌های دیگر SMOS که شبکه‌های اجتماعی شخص ثالث هستند، وبسایت یک پلتفرم **مالکیتی** با کنترل کامل سازمانی است. این سند چگونگی اداره، انتشار، نگهداری و بهینه‌سازی وبسایت را به عنوان مرکز اکوسیستم SMOS تعریف می‌کند.

وبسایت مقصد نهایی همه مسیرهای مخاطب در SMOS است — هر پلتفرم (اینستاگرام، لینکدین، تلگرام، یوتیوب و غیره) مخاطب را به وبسایت هدایت می‌کند. وبسایت حافظه دائمی برند، مخزن دانش و SSOT انتشار تمام محتوای سازمانی است.

این سند شامل ۳۴ بخش است که همه جنبه‌های عملیاتی وبسایت را پوشش می‌دهد: از هویت و مأموریت تا قواعد تولید محتوا، سئو، معماری دانش، همکاری با Agentها و بلوک‌های ماشین‌خوان.

## ۲. Purpose

### اهداف PLAT-007

۱. **تعریف نقش Hub وبسایت**: وبسایت به عنوان مرکز اکوسیستم SMOS — SSOT انتشار، حافظه دائمی، مقصد نهایی
۲. **کیفیت پایدار محتوا**: استانداردهای یکسان برای همه انواع محتوای وبسایت (مقاله، مستند، محصول، دانش)
۳. **سئوی سازمانی یکپارچه**: بهینه‌سازی ساختار URL، Schema.org، Core Web Vitals، لینک‌های داخلی
۴. **معماری دانش**: سازماندهی محتوا به صورت دانش‌محور برای انسان و Agent
۵. **خودکارسازی هوشمند**: انتشار، به‌روزرسانی، استخراج دانش و تحلیل توسط Agentها
۶. **یکپارچگی با کل SMOS**: وبسایت مرجع همه پلتفرم‌ها و مخزن نهایی دانش

## ۵. Platform Overview

## ۱۹. Caption Guidelines

### راهنمای نگارش محتوای وبسایت

وبسایت «کپشن» به معنای شبکه‌های اجتماعی ندارد. این بخش قواعد نگارش عناصر متنی وبسایت را تعریف می‌کند:

#### عنوان (Title)

| قاعده      | مقدار                                            |
| ---------- | ------------------------------------------------ |
| طول        | ۴۰-۷۰ کاراکتر                                    |
| کلمه کلیدی | در ابتدای عنوان                                  |
| لحن        | رسمی + دعوت‌کننده (طبق BRD-002)                  |
| ساختار     | [کلمه کلیدی] — [وعده/ارزش]                       |
| مثال       | "سئوی فنی: ۱۰ راهکار برای بهبود Core Web Vitals" |

#### توضیحات متا (Meta Description)

| قاعده           | مقدار                                                                                                                      |
| --------------- | -------------------------------------------------------------------------------------------------------------------------- |
| طول             | ۱۵۰-۱۶۰ کاراکتر                                                                                                            |
| شامل کلمه کلیدی | بله — در ابتدا                                                                                                             |
| CTA             | بله — دعوت به کلیک                                                                                                         |
| مثال            | "با ۱۰ راهکار عملی سئوی فنی برای بهبود Core Web Vitals آشنا شوید. راهنمای کامل بهینه‌سازی LCP, FID و CLS برای وبسایت شما." |

#### H1 (عنوان اصلی)

| قاعده         | مقدار                            |
| ------------- | -------------------------------- |
| تعداد در صفحه | دقیقاً ۱                         |
| محتوا         | منطبق با Title (تفاوت جزئی مجاز) |
| طول           | ۴۰-۷۰ کاراکتر                    |

#### H2 / H3 (زیرعنوان)

| قاعده           | مقدار                    |
| --------------- | ------------------------ |
| ساختار          | سلسله‌مراتبی — H2 سپس H3 |
| شامل کلمه کلیدی | هر H2 حداقل یک بار       |
| طول H2          | ۳۰-۶۰ کاراکتر            |
| طول H3          | ۲۰-۴۰ کاراکتر            |

#### Alt Text تصاویر

| قاعده           | مقدار                    |
| --------------- | ------------------------ |
| الزامی          | بله — همه تصاویر         |
| طول             | ۱۰-۱۵ کلمه               |
| شامل کلمه کلیدی | در صورت relevance        |
| ساختار          | توصیف کامل تصویر + زمینه |
