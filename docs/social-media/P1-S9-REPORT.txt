  Level 1 — Categories (11):

    Trust Building, Interactive, Event, Knowledge, Crisis, Internal

  Level 2 — Content Types (42):
    Each with canonical CT-ID (CT-001 through CT-042)

  Level 3 — Formats:
    article, video, image, audio, infographic, interactive, mixed

Plus Platform Version as adaptation layer (from ARCH-011 OBJ-005).

10. RISKS
--------------------------------------------------------------------------------
  1. Taxonomy complexity (MEDIUM)
     → 42 types across 11 categories may overwhelm authors
     → Mitigation: Clear hierarchy, reading guide, training materials

  2. CT-ID drift (LOW)
     → Content types may blur over time
     → Mitigation: Regular audits, clear definitions with examples

  3. Cross-platform inconsistency (MEDIUM)
     → Same CT interpreted differently across platforms
     → Mitigation: Platform Independence principles (PI-01 to PI-05)

  4. AI misclassification (MEDIUM)
     → Agent incorrectly assigns CT-ID to content
     → Mitigation: Confidence thresholds, human review for critical types

  5. Future type conflicts (LOW)
     → New CT may overlap with existing
     → Mitigation: FCT-01 to FCT-06 rules for adding new types


11. OPEN QUESTIONS
--------------------------------------------------------------------------------
  1. Should CT-IDs be extended to include sub-types (e.g., CT-001-A,
     CT-001-B)? Current design uses flat numbering with Secondary Types.

  2. Is 42 content types sufficient for the next 3 years of SMOS
     operation? The framework allows extension to CT-999.

  3. Should crisis content types (CT-036 to CT-038) have a separate
     accelerated approval workflow defined in AUT-*?

  4. Should the Content ID format include a CT-ID prefix for easier
     identification (e.g., CONT-EDU-2026-06-27-001)?

  5. Should there be a machine-readable taxonomy registry (JSON file)
     separate from the human-readable document?
